Milestone 1 — User Management, Authentication & Session Handling
Description:
Set up a dual-mode access system to distinguish between guest and authenticated users.

Authenticated Users: Can log in, have their chat and message history persist across sessions, and retrieve past recommendations.

Guest Users: Can use the system without logging in, but their session is temporary, and history is not retained after expiration.

Shared Features: Both modes can interact with the LLM, but authenticated users will benefit from personalization and history continuity.

Technical Requirements:

Authentication via OAuth (e.g., Microsoft Entra ID) or Email/Password.

PostgreSQL for storing:

User profiles (role, preferences)

Chat history (messages, timestamps, persona context)

System prompt relationships (for context recall)

Session management (JWT or server session store).

Expected Outcome:

Fully functional user identity system.

Chat history tied to user accounts in DB.

Guest mode with auto-expiration after defined inactivity period.
Milestone 1 — Persona Creation & Context Management Layer
Description:
Develop the core conversation intelligence layer that:

Generates a user travel persona from the initial prompt — covering preferences like budget, dietary restrictions, travel style, preferred climate, and trip duration.

Applies content moderation to filter out obscene or irrelevant inputs, replacing them with generic non-committal responses when detected.

Manages conversation context efficiently — tracking chat history, summarizing older portions of the conversation once a token threshold is reached, and merging summaries with recent messages to preserve key details while minimizing token usage.

Expected Outcome:

Structured persona object stored for each user and used to guide recommendations.

Moderation system that detects off-topic or harmful content before it reaches the LLM.

Summarization engine that reduces token load without losing crucial context.

Dependencies:

OpenAI / LLaMA for persona generation and summarization.

OpenAI moderation API or custom classifier for content filtering.

PostgreSQL (with pgvector) for storing persona data, chat logs, and summaries.
Milestone 1 — Persona Creation Engine
Description:
Implement an LLM-powered persona builder that takes a user’s initial prompt (e.g., travel goals, budget, dietary preferences, travel style) and generates a structured persona profile. This persona will drive all subsequent recommendations.

Expected Outcome:

Given a user prompt, system generates a JSON persona object with attributes such as budget, dietary_preferences, preferred_climate, travel_companion_type, etc.

Persona is stored and re-used in future conversations.

Dependencies:

OpenAI / LLaMA API for prompt processing.

Embedding storage for long-term persona context.

Milestone 2 — Destination Identification & Enrichment
Description:
Extract potential travel destinations from user input, then query web sources (SERP API, Google Places API, or similar) to gather relevant travel data.
Include parameters like weather forecast, local safety advisories, political stability, and travel restrictions.

Expected Outcome:

For each identified location, the system returns a structured recommendation with rating scores based on criteria.

Ability to rank destinations dynamically.

Dependencies:

Entity extraction from LLM output.

SERP API / Google Places API / Weather API integration.

Milestone 3 — Budget-Friendly Package Finder
Description:
Using the user’s persona + current conversation context, query multiple data sources (travel APIs, hotel APIs, rental car APIs, flight APIs) to find best-match and budget-friendly travel packages.

Expected Outcome:

Aggregated package list with cost breakdown.

Ranking based on cost, convenience, and persona fit.

Dependencies:

Travel/hotel/car booking API integrations.

Ranking logic for weighted scoring.

Milestone 4 — Chat History Storage & Fine-Tuning
Description:
Persist user conversations to a database for later analysis, fine-tuning, and personalization. Include both raw conversation logs and summarized versions to save token cost.

Expected Outcome:

All chats linked to user profiles in DB.

Ability to export chat logs for fine-tuning datasets.

Dependencies:

PostgreSQL with pgvector for embeddings.

Token counting and summarization service.

Milestone 5 — Obscenity & Off-topic Filter
Description:
Introduce an LLM + rules-based moderation layer to detect and sanitize off-topic or obscene user inputs before passing them to the main LLM.

Expected Outcome:

If detected, respond with a generic non-committal message.

Maintain logs of filtered inputs for analysis.

Dependencies:

OpenAI moderation API / custom classification model.

Milestone 6 — Context Summarization Engine
Description:
When token count exceeds threshold, generate rolling summaries that combine old summary + new unsummarized messages to retain context without losing details.

Expected Outcome:

Conversation remains relevant even after long sessions.

Token usage reduced by at least 40%.

Dependencies:

Summarization prompt tuning for LLM.

DB storage for summaries alongside raw messages.

Milestone 7 — Performance & UX Enhancements
Description:
Improve response latency and user experience via:

Pre-fetching potential destinations & data in background.

Caching static travel data.

Real-time progress indicators in UI.

Expected Outcome:

Average API response time < 2 seconds for cached queries.

Dependencies:

Redis for caching.

WebSocket/SSE for streaming updates.
