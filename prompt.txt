# Improve Flight Agent Reasoning & Recovery

Review the current Flight Agent system prompt, conversation/context handling, and all available tools. Improve the prompt so the agent uses **reasoning and existing context instead of repeatedly asking the user for information that can already be inferred**.

Example failure to generalize from:

* User says dates are flexible / “any dates”.
* Later says round trip and “one month stay”.
* Agent should infer a sensible future departure date, derive the return date from the stay duration, and search.
* If `flight_search` responds with something like `departure date must be after today`, treat that as **actionable tool feedback**, correct the date, and retry instead of asking the user unnecessarily.

General behavior required:

* Priority: **current user message → current flight/search context → relevant conversation history → sensible defaults/inference**.
* Combine information collected across previous turns; do not treat every message independently.
* If enough information exists to make a reasonable search, **act instead of asking another clarification**.
* Use tool errors/validation responses as feedback. If the correction is deterministic and safe, fix the input and retry the appropriate tool.
* Use `resolve_flight_date`/other tools intelligently where useful; do not call tools mechanically.
* Ask the user only when information is genuinely ambiguous and cannot be safely inferred.
* Do not hardcode this single scenario or add dozens of phrase-specific rules. Add **general reasoning principles** that work across flight-search scenarios.
* Never invent critical information when multiple materially different interpretations are possible.

Keep the change minimal and clean. Do not modify existing business rules/tool contracts unless required. After updating the prompt, test it against this scenario plus several similar multi-turn/flexible-date/tool-error scenarios and report what improved and any remaining gaps.
