Enhance our existing **App Insights event tracking** for Flight Agent's external API and database operations.

### APIs to Track

1. **Flight Search Tool:** Digital API requests.
2. **Price Prediction Tool:** Database queries used for price prediction.
3. **Apply Filter Tool:** Filter API requests.

### Requirements

For every API/DB execution, emit a structured App Insights event containing:

- Operation/tool name and request ID.
- Request payload or DB query parameters.
- Execution duration in milliseconds.
- Result status: `success`, `failure`, `no_results`, or `timeout`.
- Error details when failures occur.
- Relevant response metadata, such as result count.

### Implementation

- Inspect our existing App Insights integration and reuse its event-tracking patterns.
- Add events at the actual API/DB execution points, including retries and failed attempts.
- Track empty results separately from API failures.
- Preserve correlation with the originating chat request.
- Exclude credentials, tokens, and sensitive user information from logged payloads.
- Keep existing API behavior unchanged.

**Important:** Keep implementation minimal. Avoid unnecessary wrappers, duplicate events, or additional logging infrastructure.

Implement and verify tracking for all three operations, including successful, failed, timeout, and empty-result scenarios.

**Goal:** Make it easy to identify which API or DB operation failed, what safe request parameters were used, and how long execution took through App Insights.
