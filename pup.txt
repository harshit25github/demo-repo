Task:
Debug why updated agents/system prompts are not showing for a specific App ID.

Context:
We have app-level routes.

Flow:
1. Admin token is used to fetch the list of apps.
2. Each app represents a service.
3. Each app can use multiple agents.
4. Each agent has its own system prompt.
5. Using App ID, we fetch all agents and system prompts linked to that app.

Current Issue:
The app list is getting retrieved correctly using the admin token.
But when fetching agents/prompts by App ID, the latest/updated agents are not showing.

Possible Problem:
It looks like updated agents may not be getting saved/linked properly in the database, or the App ID mapping is not updated correctly.

Your Task:
Do not fix directly first.
Debug and identify the root cause.

Please check:
- app list API response using admin token
- App ID being passed correctly
- DB records for the selected app
- agent-to-app mapping table/relationship
- whether updated agents are saved in DB
- whether updated prompts are saved in DB
- whether old/cached data is being returned
- whether query filters are excluding updated agents
- whether environment/database mismatch exists
- whether migration/seed/update logic is missing
- whether API response mapping is dropping agent/prompt fields

Expected Output:
Provide a root-cause analysis with:
- what API is working
- where the data is missing
- whether issue is in DB save, DB relation, query, cache, or response mapping
- files/functions/routes involved
- logs or DB queries used to verify
- suggested fix plan

Acceptance Criteria:
- Confirm whether updated agents exist in DB.
- Confirm whether they are linked to the correct App ID.
- Confirm why agents/prompts are missing from App ID response.
- Provide a clear fix plan before implementation.
