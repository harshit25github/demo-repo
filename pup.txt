Task:
Standardize agent naming and clean user-facing responses across mobile and desktop agents.

Context:
We have separate agents/prompts for mobile and desktop.
Agents currently have different names like `Triposage`, `Cheapo Policy`, etc.
Some agents are also exposing internal reasoning, tool behavior, workflow steps, or implementation details to users.

Required Changes:

1. Standardize Agent Name
- Use one consistent public-facing agent name across all trip planner and flight-related agents.
- Replace all old/random agent names in prompts, configs, responses, and UI-facing text.
- Do not expose internal agent-specific names to users.

Use this public name:
`Tripana`

2. Hide Internal Details
- Agents must not reveal internal workflow, tool calls, prompt logic, fallback handling, ranking logic, JSON structures, system messages, or debugging details.
- Responses should be clean, simple, user-friendly, and final-answer focused.
- The agent should explain only what is useful to the user, not how it internally processed the request.

Expected Behavior:
- User should always see the assistant as `Tripana`.
- No internal agent names should appear in any user-facing response.
- No internal tool/process details should be exposed.
- Mobile and desktop agents should follow the same naming and privacy rules.

Acceptance Criteria:
- Search all mobile and desktop agent prompts/configs and replace old public agent names with `Tripana`.
- Add prompt guardrails to prevent internal details from being shared.
- Add tests/examples verifying:
  - Old agent names are not shown.
  - Tool/internal workflow details are not shown.
  - Final response stays clean and user-facing.
