Task:
Create a consistent response flow for agent identification and capability-related queries.

Context:
All user requests first go to the orchestrator.
The orchestrator then routes the request to agents like:
- Trip Planner Agent
- Flight Agent
- Policy Agent

Currently, when users ask identity/capability questions, the orchestrator redirects them to different agents.
Because each agent has its own response style, the output becomes inconsistent.

Example User Queries:
- What is your name?
- Who are you?
- What can you help me with?
- What kind of queries can you solve?
- Are you a flight agent?
- Can you help me plan a trip?
- Can you explain policies?

Required Enhancement:
Handle all agent identification and capability-related queries with one consistent response style.

Expected Behavior:
- The orchestrator should detect identity/capability intent.
- These queries should not be routed randomly to Flight, Trip Planner, or Policy agents.
- Either handle them directly at the orchestrator level, or route them to a dedicated common identity/help handler.
- The response should always use the same tone, structure, and agent name.
- Do not expose internal agent names, routing logic, tools, workflows, or system details.

Public Agent Name:
Use `Tripana` as the user-facing assistant name.

Response Guidelines:
- Keep the response short, clean, and user-friendly.
- Explain what Tripana can help with at a high level.
- Mention capabilities like:
  - trip planning
  - flight search
  - flight filtering
  - baggage/policy help
  - travel-related assistance
- Do not mention internal agents like Flight Agent, Policy Agent, Trip Planner Agent, or orchestrator.

Sample Response:
"Hi, I’m Tripana. I can help you plan trips, search flights, compare options, apply travel filters, and answer travel policy or baggage-related questions. Tell me what you’re planning, and I’ll help you with the next step."

Acceptance Criteria:
- Identity/help queries return a consistent response every time.
- Response style does not change based on routed agent.
- Internal agent names are never exposed.
- Orchestrator correctly classifies these queries before routing.
- Add tests for:
  - “Who are you?”
  - “What can you do?”
  - “Can you help with flights?”
  - “What kind of queries can you solve?”
  - “Are you a policy agent?”
