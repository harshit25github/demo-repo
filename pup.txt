Investigate and plan improvements to our **Human Handoff Guardrail**, which currently behaves inconsistently.

### Current Expected Behavior

1. **Search criteria already available:** Directly trigger human handoff.
2. **No search criteria available:** Perform a soft handoff first, encouraging the user to plan/search before connecting.
3. **User insists after soft handoff:** Trigger human handoff, even if search criteria is still missing.

### Current Problem

For multi-turn conversations such as:

- User: "I need to speak to someone live."
- Agent: Provides a soft-handoff message.
- User: "No, I still want to speak to someone before purchasing."

Sometimes the guardrail triggers human handoff correctly, but sometimes it fails.

### Your Task

- Thoroughly inspect the existing Human Handoff Guardrail, prompts, conversation history, and state handling.
- Identify why repeated handoff requests are inconsistently classified.
- Explore whether we need better context awareness, explicit soft-handoff state tracking, improved prompting, or another minimal solution.
- Compare possible approaches and recommend the most reliable one.
- Prepare multi-turn test scenarios covering direct handoffs, soft handoffs, repeated requests, missing search criteria, and existing search criteria.
- Provide an evidence-based root cause and a minimal implementation and testing plan.

**Important:** R&D and planning only. Do not implement yet. Avoid unnecessary wrappers or complex custom logic.

**Goal:** Make human handoff consistent: soft handoff when appropriate, but always respect a user's repeated request to speak with a human.
