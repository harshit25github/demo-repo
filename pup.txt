Task:
Remove `status guardrail triggered` chunk from the first human handoff request.

Context:
Human handoff confirmation flow is already working.
On the first request, we only ask user for confirmation.
On the second confirmed request, we trigger the actual handoff.

Issue:
Currently, the first request also streams a chunk like `status guardrail triggered`.
This can confuse the client because first request is not the final handoff trigger.

Required Change:
- Do not send `status guardrail triggered` on the first human handoff request.
- First request should only stream the confirmation message.
- Keep second request behavior unchanged.
- On second confirmation, existing guardrail/tripwire status can be sent.

Acceptance Criteria:
- First request has no `status guardrail triggered` chunk.
- Confirmation message still works.
- Second request still triggers handoff correctly.
