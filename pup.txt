Investigate and plan a solution for **infinite/repeated tool-call loops** in our agent execution.

### Current Problem

Rarely, agents repeatedly invoke the same tools for 2–5+ minutes until the client aborts and reports a connection-lost error.

Previously, we addressed a similar issue with `update_suggested_questions` by disabling the tool after its first invocation within a user turn.

### R&D Requirements

1. Inspect all agent tools across **Gateway V1 and Manager V2**, including their execution and retry behavior.
2. Analyze logs/traces to identify repeated calls, legitimate multi-step invocations, and actual loops.
3. Determine a reasonable **per-tool maximum call count per user turn**, based on each tool's purpose and real usage.
4. Explore OpenAI Agents SDK capabilities for dynamically enabling/disabling tools during execution.
5. Evaluate how to track invocation counts per request and disable a tool once its limit is reached.
6. Ensure limits reset on every new user turn and don't interfere with legitimate retries or multi-agent execution.
7. Define graceful recovery when a tool reaches its limit, so the Agent can respond intelligently instead of looping or failing.

### Important

- Avoid one global limit for every tool.
- Preserve legitimate search → filter → re-search workflows.
- Keep implementation minimal, without unnecessary wrappers or complex tracking layers.
- **R&D and planning only. Do not implement yet.**

**Expected Output:** Root cause, recommended per-tool call limits, SDK implementation approach with code examples, affected files, and testing strategy.

**Goal:** Prevent runaway tool-call loops while preserving valid agent workflows and reducing unnecessary latency and token costs.
