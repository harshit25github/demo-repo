## 1. Architecture at a glance (EXISTING)

```text
 Client ── POST /api/ingest {urls[] | urlsFile, force?, collection?} ──► RPA Airline RAG (Node/Express)
                                                                        IngestJobManager (in-memory queue, concurrency 1)
                                                                          └─ IngestionService.ingestUrls()
        ┌──────────── (1) POST /crawl/jobs {schemaVersion:1, requestId, urls[]} ◄──────────────┘
        ▼
 Crawler API (FastAPI)  ── PostgreSQL: crawl_jobs / crawl_targets / crawl_results(result_payload JSONB)
        ▲                                   ▲
        │                         Crawler Worker (python -m crawl_service.worker)
        │                         claim (lease 60 s, heartbeat 20 s) → Crawl4AI 0.9.3 → persist every page
        │                         finalize job → (2) HMAC-signed POST /api/internal/crawl-events  ──► Node (wake-up only)
        │
        ├── (3) GET /crawl/jobs/{jobId}                 Node polls at 5 s, 10 s, 20 s, then every 30 s (or woken by the webhook)
        └── (4) GET /crawl/jobs/{jobId}/results?limit=25&cursor=…   Node reads every page after terminal status
                         │
                         ▼
   Node: validate → normalize → chunks / facts / directory rows → OpenAI embeddings → Qdrant upsert + prune
         + artifacts: data/crawl4ai, data/raw, data/chunks, data/traces, *.indexed.json markers
```

### Ownership split (the central design decision)
- **The crawler owns**: profile, depth, and policy resolution (the client sends **only URL strings**); BFS and child discovery; retries and anti-bot handling; SSRF and robots checks; durable job state; result storage (7-day retention); the terminal webhook.
- **Node owns**: one crawler job per ingest request; waiting for it; consuming all results; re-validating every returned page (host, redirect, depth, alias); enrichment from CheapOair baggage-directory rows; quality gates; chunking; embeddings; Qdrant writes; local artifacts; change detection.
- **Node does not** crawl, discover children, batch URLs, retry pages, or send profile, depth, or policyKey. Older generations did all of this (see §8).
- **Completion does not push data into indexing.** The ingest job's own async function waits (polling, accelerated by the webhook). Once the status is terminal, that same function fetches the results and indexes them. The webhook never fetches results and never starts indexing.

### Storage
The local reference has **no relational database on the Node side**:
- **Crawler PostgreSQL**: jobs, targets, and complete page payloads, owned by Python.
- **Node filesystem**: artifacts under `data/`.
- **Qdrant**: vectors plus payload.

If production indexing also writes to a SQL or other database, report it as FOUND. Do not assume either way.

## 2. End-to-end sequence (EXISTING)

1. **`POST /api/ingest`** → `handlers.ingest` → `IngestJobManager.createJob(body)`.
   - Body: `{ urls?: string[], urlsFile?: string, force?: boolean, collection?: string }`. `urlsFile` is resolved relative to `process.cwd()`.
   - Returns **202** `{ jobId: "ingest_<base36 ms>_<8 hex>", collection, status: "queued", statusUrl: "/api/ingest/jobs/<jobId>" }`.
   - Job state is an in-memory `Map` (retention 100 jobs, concurrency 1). Status: `GET /api/ingest/jobs/:jobId`; list: `GET /api/ingest/jobs`.
2. **Drain** → `runJob(job)` → `kb.ingestUrls(urls, { force, collection, requestId: job.jobId, onProgress })`. **The ingest `jobId` is reused as the crawler `requestId`**, serving as both the idempotency key and the correlation ID.
3. **`IngestionService.ingestUrls`** (Appendix A6):
   1. `prepareIngestTargets`: trim, dedupe by `crawlUrlIdentity`, tag the CheapOair directory URL `crawlProfile:"directory"` (everything else `"standard"`), and resolve the airline policy by hostname from `config/crawl-policies.json` (`airlineName`, plus `airlineCanonical` = policy key). `crawlProfile` is local metadata only and is never sent.
   2. Targets whose policy has `skipIngestion` are still sent to the crawler, which marks them `skipped`. Node reports them as `skipped` with reason `airline_ingestion_disabled`.
   3. **One** `createCrawlJob({ schemaVersion: 1, requestId, urls })` call, up to 1,000 URLs. More than 1,000 fails zod validation before any HTTP call.
   4. Poll `getCrawlJob(jobId)` until the status is `completed`, `completed_with_errors`, or `failed`. Each wait is `waitForCrawlJobSignal(jobId, delay)` with delays 5 s → 10 s → 20 s → 30 s, then 30 s repeating. A webhook resolves the current wait early.
   5. Read **every** results page by following the opaque `nextCursor`. A repeated or missing cursor throws "invalid cursor chain".
   6. Convert each item to a crawl page. Parse depth-0 directory pages into rows, then into linked-target metadata (airline name and aliases, keyed by URL identity). This parsing never schedules another crawl.
   7. Build per-page contexts. `policyKey = item.policyKey || <seed target policy> || resolve(airlineSeedUrl || url)`. `airlineDepth = airlineSeedUrl ? max(0, depth - 1) : depth`.
   8. Enabled targets with no returned page are marked `failed`: `crawl_job_failed` if the job failed, otherwise `crawl_target_failed`.
   9. Validate pages in depth order, assigning one of these reasons: `crawl_failed`, `invalid_url`, `outside_airline_hosts`, `insecure_redirect`, or `already_crawled_alias` (the last one becomes `skipped`).
   10. Index accepted pages with `INGEST_CONCURRENCY` (default 3) through `ingestPreparedUrl` → `ingestUrl` (§4). A thrown error becomes `failed` with reason `no_text_extracted`, `no_chunks_produced`, or `indexing_error`.
   11. Write a run manifest to `data/crawl4ai/runs/<iso>-<uuid>.manifest.json`. Return `{ seedTotal, total, ingested, skipped, failed, collection, crawlerJobId, crawlerStatus, crawlSummary, crawlManifestPath, crawlManifests, results[] }`.
4. **Job outcome**: the job becomes `succeeded` when `ingestUrls` returns, even if some pages failed (per-page outcomes are in `result.results[]`). It becomes `failed` when `ingestUrls` throws, for example on a crawler 4xx, a 404 for an expired job, or a cursor error.
5. **Progress stages** (`progress.stage`): `queued` → `ingesting` → `crawling` → `waiting_for_crawl` → `crawling` (one per poll) → `validating_pages` → `indexing` → `ingesting` (per page) → `succeeded` | `failed`. Progress also carries `crawlerJobId`, `crawlerStatus`, `crawlSummary`, and the counters.

## 3. Service contracts (EXISTING; the crawler side is deployed, so verify it and do not change it)

### 3.1 Authentication and transport
- **Node → crawler**: `Authorization: Bearer ${CRAWL4AI_API_TOKEN}` on every `/crawl/jobs*` call. The header is sent only when the token is configured. The crawler compares with `secrets.compare_digest`. **If the crawler's `CRAWL4AI_API_TOKEN` is empty, authentication is disabled** and any caller is accepted (Appendix B2), so production must set it on both sides. `/health` and `/ready` are unauthenticated.
- **Crawler → Node**: HMAC-SHA256 signature using the shared `CRAWL_WEBHOOK_SECRET`.
- **Node timeouts**: POST 15 s (`CRAWL_JOB_CREATE_TIMEOUT_MS`); GET 30 s (`CRAWL_JOB_REQUEST_TIMEOUT_MS`).
- **Node retries**: POST up to 3 attempts, each GET up to 5 attempts. Only network errors, timeouts, and HTTP ≥ 500 are retried, with backoff 1 s, 2 s, 4 s, 8 s (capped at 16 s). **4xx responses are never retried**, including 401, 404, 409, 422, and 429.

### 3.2 Create a job: `POST /crawl/jobs`
Request (strict; any extra field returns **422**):
```json
{ "schemaVersion": 1, "requestId": "ingest_mo0phish_f21c43d3", "urls": ["https://www.cheapoair.com/travel/baggage-fees/"] }
```

**Validation:**
- `requestId`: 1–200 characters matching `^[A-Za-z0-9._:-]+$`.
- `urls`: 1–1,000 entries, HTTP(S) only, no credentials, no non-public IP literals.
- The server normalizes each URL (lowercases scheme and host, drops the fragment, turns an empty path into `/`, **keeps any trailing slash**) and removes duplicates.

**The server infers each target's profile** (Appendix B3 and §3.8):
- The directory URL (`CRAWL_BAGGAGE_DIRECTORY_URL`, default `https://www.cheapoair.com/travel/baggage-fees/`, matched **exactly** after normalization) becomes `baggage_directory`, crawled to global depth 2 for enabled airline codes.
- A URL whose host is in an airline policy's `allowedHostnames` and that equals a seed or matches `allowedUrlPatterns` becomes `airline` (with `policyKey`), or `skipped` if that policy has `skipIngestion`.
- Anything else becomes `standard` (a single page).

**Responses:**

| Status | Meaning |
|---|---|
| 202 | New job created. |
| 200 | Same `requestId` with an identical canonical payload. Idempotent replay that returns the existing job. |
| 409 | Same `requestId` with a different payload. |
| 429 | Queue full; `Retry-After: 30`. The cap is `CRAWL_MAX_QUEUED_JOBS` (default 100) queued plus running jobs. |
| 401 | Invalid token. |
| 422 | Schema validation failed. |

Response body:
```json
{ "schemaVersion": 1, "jobId": "crawl_<32hex>", "requestId": "ingest_…", "status": "queued", "targetTotal": 1,
  "statusUrl": "/crawl/jobs/crawl_<32hex>", "resultsUrl": "/crawl/jobs/crawl_<32hex>/results", "createdAt": "2026-…Z" }
```

### 3.3 Job status: `GET /crawl/jobs/{jobId}`
- **Fields**:
  - `schemaVersion`, `jobId`, `requestId`, `status` (`queued`, `running`, `completed`, `completed_with_errors`, or `failed`).
  - Target counts: `targetTotal`, `targetQueued`, `targetRunning`, `targetCompleted`, `targetPartial`, `targetFailed`, `targetSkipped`.
  - Result counts: `resultTotal`, `resultSucceeded`, `resultFailed`, `warningCount`.
  - `resultsReady` (true once the status is terminal), `createdAt`, `startedAt`, `completedAt`, `errorCode`, `errorMessage`.
- **404** for an unknown or expired job (retention deletes jobs).
- **Terminal status rules** (`repository.finalize_job`):
  - `failed` when a job-level error occurred and nothing succeeded.
  - `completed_with_errors` when at least one page succeeded and there is any failed result or any partial/failed target.
  - `completed` when pages succeeded with no problems, or when every target was skipped.
  - Otherwise `failed` with error code `no_successful_results`.

### 3.4 Results: `GET /crawl/jobs/{jobId}/results?limit=25&cursor=…`
- Readable only after a terminal status; otherwise **409** "Crawl results are not ready."
- `limit` is 1–100. The cursor is opaque (base64url of `v1:target_order:depth:sequence`): **never construct it**. An invalid cursor returns **400**.
- Order: target submission order, then depth, then sequence.
- Every stored payload is checksum-verified on read (**500** on mismatch).
- Response: `{ schemaVersion: 1, jobId, status, items: [...], nextCursor, hasMore }`. One item:
```jsonc
{
  "resultId": "result_<32hex>", "targetId": "target_<32hex>", "sequence": 14,
  "seedUrl": "https://www.cheapoair.com/travel/baggage-fees/",          // the submitted target
  "airlineSeedUrl": "https://www.aa.com/…/checked-baggage-policy.html", // set on directory-derived items (depth >= 1)
  "parentUrl": "https://www.aa.com/…", "url": "https://www.aa.com/…/pets", "redirectedUrl": null,
  "depth": 2, "policyKey": "american", "success": true, "statusCode": 200,
  "errorCode": null, "errorMessage": null,
  "rawMarkdown": "…", "fitMarkdown": null,
  "metadata": { "…crawl4ai metadata; may include airline_seed_url, failure_source, expansion_warning": "…" },
  "links": {}, "sslCertificate": null,
  "crawlStats": { "attempts": 1, "retries": 0, "profileUsed": "airline", "proxyUsed": false, "recoveryAction": null },
  "dispatchResult": null, "warningCode": null, "contentChecksum": "sha256:<hex>"
}
```

**Depth semantics:**
- **`standard` target**: depth 0 only.
- **`airline` target**: depth 0 is the submitted seed; depth 1 holds approved children (server-side BFS with domain, path, topic, and content-type filters, at most 20 extra pages per policy group).
- **`baggage_directory` target**:
  - Depth 0 is the directory page.
  - Depth 1 is each exact "View policy" airline page, with `airlineSeedUrl` set to that page.
  - Depth 2 holds the children of selected airline pages (`policyKey` set).
  - Every directory-derived item carries `seedUrl` = the directory URL.
  - If the page has no "View policy" links, the root item gets `warningCode = "no_view_policy_links"`.
- Failed pages are stored too, with `success: false` and a stable `errorCode`.

### 3.5 Terminal webhook: crawler `CRAWL_COMPLETION_WEBHOOK_URL` → Node `POST /api/internal/crawl-events` (Appendix A2, A3, B1)
- **Configuration**: set only on the crawler, through env; it is not per job. The worker sends one event per terminal job.
- **Headers**:
  - `content-type: application/json`
  - `x-crawl-timestamp: <unix seconds>`
  - `x-crawl-signature: v1=<hex HMAC_SHA256(secret, "<timestamp>." + rawBody)>`
- **Body** (compact JSON, validated strictly):
  ```json
  {"schemaVersion":1,"eventId":"crawl_<hex>:terminal:v1","type":"crawl.job.completed","jobId":"crawl_<hex>","requestId":"ingest_…","status":"completed","resultTotal":42,"resultsUrl":"/crawl/jobs/crawl_<hex>/results","completedAt":"…Z"}
  ```
  `type` is `crawl.job.<status>`, where status is `completed`, `completed_with_errors`, or `failed`.
- **Crawler delivery**:
  - The first attempt happens at finalize. Any exception or non-2xx response is retried at +5 s, +15 s, +45 s, +120 s, and +300 s, for **at most 6 attempts**, each with a 15 s timeout.
  - Delivery runs inside the single worker loop, between jobs, so retries can wait while a long job runs.
  - **Polling remains authoritative.** The integration works without the webhook; it is just up to 30 s slower.
- **Node receiver**:
  - Requires both headers and a timestamp within 300 s of now.
  - Compares the HMAC over the **exact raw bytes** with a timing-safe check, then applies a strict zod schema.
  - Returns **204** on success, on a duplicate, and for an unknown job.
  - Returns **401** for a bad or stale signature, and **503** if `CRAWL_WEBHOOK_SECRET` is unset in Node.
  - Effects: dedupe by `eventId` (in-memory Set); set `progress.crawlerJobId` and `progress.crawlerStatus` on the job matched by `requestId === ingest jobId` or by `crawlerJobId`; call `crawl4aiClient.notifyCrawlJob(jobId)` to wake the poller.
- **Raw-body requirement**: `express.json({ verify })` stores `request.rawBody` only when `request.path === "/api/internal/crawl-events"`. If production mounts routes under a prefix, uses another JSON parser earlier in the chain, or sits behind a proxy that re-serializes JSON, the signature check fails with 401. Adapt the path check to production's mounting.
- **Crawler configuration gotcha** (deployed code; configuration only): if `CRAWL_COMPLETION_WEBHOOK_URL` is set but `CRAWL_WEBHOOK_SECRET` is empty, `deliver_due_webhooks` raises a `RuntimeError` that the worker loop does not catch, and **the worker process exits**. Set both or neither.

### 3.6 Health
- `GET /health` → `{ "status": "healthy", "serviceVersion": "2.0.0", "crawl4aiVersion": "0.9.3", "policySchemaVersion": 1 }`
- `GET /ready` → `{ "status": "ready" }`, or **503** if PostgreSQL is unavailable.

### 3.7 Identifier map

| ID | Format | Created by | Purpose |
|---|---|---|---|
| ingest `jobId` | `ingest_<base36 ms>_<8 hex>` | Node `IngestJobManager` | Public status URL. Sent to the crawler as `requestId`. |
| `requestId` | Same as the ingest `jobId` (or `ingest_<uuid>` when `ingestUrls` is called directly) | Node | Crawler idempotency (UNIQUE plus payload hash) and webhook correlation. |
| crawler `jobId` | `crawl_<32 hex>` | Crawler | Status and results URLs, webhook `jobId`, poller wake-up key. |
| `eventId` | `<jobId>:terminal:v1` | Crawler | Webhook dedupe. |
| `targetId` / `resultId` | `target_<32 hex>` / `result_<sha256 prefix>` | Crawler | Deterministic per target+URL result key. Retries upsert the same row. |
| `docId` | `hashToUuid(normalizeUrlForIdentity(finalUrl))` | Node | Qdrant document identity and refresh-lock key. |
| Qdrant point IDs | chunk `hashToUuid(docId:index)`; fact `hashToUuid(sectionId:facet)`; row `hashToUuid(docId:row:<airlineSlug>:<routeSlug>:<index>)` | Node | Idempotent upserts: re-indexing overwrites the same IDs. |

### 3.8 Crawler worker behavior relevant to Node (deployed; summary)

**Worker loop** (`run_worker`):
- Migrate the database on start.
- Hourly retention cleanup.
- Deliver due webhooks.
- Claim the next job with `FOR UPDATE SKIP LOCKED`; the lease is 60 s, extended by a heartbeat every 20 s.
- Run it with a 6 h timeout.
- `finalize_job`, then deliver the webhook.

**Inside a job:**
- One headless Chromium crawler.
- Targets are processed in groups:
  - All `standard` URLs go in one batched run.
  - Each directory target runs on its own: root page, then "View policy" links, then a deep BFS for selected airlines, with single depth-1 pages in batches of 25 for the rest.
  - Airline targets run grouped by `policyKey`.
- Every page is persisted the moment it finishes, with a deterministic result key and a checksum.
- Each target is capped at 2 worker attempts, after which it gets `worker_attempts_exhausted`.
- An expired lease lets another worker reclaim the job, and its running targets are re-queued.

**Retention and capacity:**
- Retention is 7 days: the job and its targets and results are cascade-deleted. **Node must consume results within that window.**
- The queue cap is 100 queued plus running jobs.

## 4. Indexing lifecycle per page: `IngestionService.ingestUrl(url, options)` (EXISTING; Appendix A7)

`options.crawlPage` is **required**; without it the function throws "ingestUrl requires an already crawled page…". Node never crawls at this point.

1. **Policy**: resolve the airline policy. If `skipIngestion` is set, return `skipped` with reason `airline_ingestion_disabled`.
2. **Paths**: `fileStemForUrl(url)` builds a stem from the host and path slug plus `sha256(normalized URL)[0:12]`. Files:
   - `data/crawl4ai/<stem>.json`
   - `data/raw/<stem>.json`
   - `data/chunks/<stem>.json`
   - `data/traces/<stem>.trace.json`
   - Marker: `data/raw/<stem>.json.<sha256(collection)[0:16]>.indexed.json`
3. **`buildRawDocFromCrawlPage`** (A8):
   - Text is the first non-empty of `markdown.fit`, then `markdown.raw`, then the other fallbacks. It throws if the page failed or has no text.
   - `rawDoc = { docId, url (final), domain, title, fetchedAt, cleanedText, contentHash: sha256(text), metadata }`.
   - `title` is `metadata.title` or the first heading.
   - `metadata` holds `requestId`, `source: "crawl4ai-adapter"`, `seedUrl`, `parentUrl`, `crawlDepth`, `policyKey`, `crawlMetadata`, `statusCode`, `redirectedUrl`, `sslCertificate`, `crawlStats`, and `dispatchResult`.
4. **`buildVectorArtifacts(rawDoc, { targetChars, overlapChars, airline identity })`** (A9):
   - **`normalizeDocument`** (A13):
     - `sourceType` comes from the URL: `privacy_policy`, `cookie_policy`, `terms_conditions`, `service_fees`, `post_ticketing_fees`, `baggage_directory`, `rewards_program`, or else `airline_policy`.
     - `cleanupMarkdown` removes pre-heading boilerplate, tables of contents, navigation, and link-heavy lines, and trims airline lead and tail sections.
     - Airline identity: the configured policy name wins; otherwise it is derived from site metadata, the title, or the URL.
     - `classifyQuality` returns `qualityStatus` (`usable` | `unusable`), `authority` (`primary` | `discovery_only` | `unusable`), and `retrievalAllowed`.
     - URL alias variants are added.
   - **`chunkDocument`**: heading-aware markdown chunks of `CHUNK_TARGET_CHARS` (4500) with `CHUNK_OVERLAP_CHARS` (500) of paragraph overlap. Each chunk keeps its `sectionPath`. Record type `section_chunk`.
   - **`airline_policy` pages**: `extractBaggageFacts` runs each section against `BAGGAGE_FACETS` (`carry_on`, `first_checked_bag`, `second_checked_bag`, `oversize`, `overweight`, `special_items`, `additional_policy`), producing `policy_fact` records with a composed `embeddingText`.
   - **`baggage_directory` pages**: `extractBaggageDirectoryRows` produces records with `sourceType: "baggage_directory_row"` and `recordType: "directory_row"`. They carry `routeScope`, carry-on cost, weight, size, and notes, and the policy URLs with their aliases.
   - Records assembled per source type: directory pages give rows plus chunks; `airline_policy` pages give facts plus chunks; everything else gives chunks only.
5. **`assessVectorArtifacts`**: failure reasons `blocked_page`, `quality_gate`, `help_shell_without_baggage_facts`, `tiny_weak_content`.
6. **Airline guard**: the page fails with `insecure_redirect` or `outside_airline_hosts` if it redirected from HTTPS to HTTP, if its final URL is outside the policy's hosts, or if `airlineDepth > extraDepth`.
7. **Change detection**:
   - `indexFingerprint = sha256({ cleanedText, chunking config, airline identity fields, sourceType, embedding model and baseUrl })`.
   - A page counts as unchanged when it is usable, its previous raw `contentHash` matches, the marker fingerprint matches, and Qdrant `hasRecords(marker.recordIds)` is true. The Qdrant check is skipped when `force` is set.
   - The crawl4ai and raw JSON files are written first. An unchanged page then returns `skipped` with reason `content_hash_unchanged`, unless `force` is set.
8. **Chunks file**: written next. No chunks → `failed` (reason from the assessment, or `no_chunks_produced`). Unusable → `failed` with the assessment reason.
9. **Embeddings**: the `embeddingText || text` of every `retrievalAllowed` record goes into **one** `POST {OPENAI_BASE_URL}/embeddings` call, with no batching and no retry.
10. **Qdrant write**, inside `withIndexRefreshLock({ collection, docId })` (A11):
    1. `ensureCollection(dim)` creates a Cosine collection, and throws if an existing collection has a different dimension.
    2. `upsertRecords` (`PUT points?wait=true`).
    3. `deleteDocument(docId, excludeIds = new IDs)`.
    4. `deleteByUrlVariants([url, canonicalUrl, redirectedUrl], excludeIds)`.
    5. Write the marker `{ fingerprint, collection, recordCount, recordIds, completedAt }`.

    Uploading before pruning keeps the previous version searchable if the upload fails.
11. **Result**: returns `{ status: "ingested", url, seedUrl, parentUrl, crawlDepth, policyKey, collection, crawl4aiPath, rawPath, chunkPath, tracePath, chunkCount, sourceType, crawlAttempts, crawlUrlAliases }`.

    ⚠ When `OPENAI_API_KEY` is missing, steps 9–10 are skipped (an `embedding_skipped` trace) but the status is **still `ingested`**, and nothing reaches Qdrant. Verify point counts in Qdrant, not just statuses.

### 4.1 Qdrant payload contract (written by `QdrantService.upsertRecords`, A10)
```text
docId, url, canonicalUrl, redirectedUrl, urlAliases[], domain, title, chunkIndex, sectionId, sectionIndex, partIndex,
sectionTitle, sectionPath[], sectionSlug, anchorText, text, fetchedAt, contentHash, textHash, sourceType, recordType,
authority, qualityStatus, retrievalAllowed, airlineName, airlineSlug, airlineCanonical, airlineNameAliases[],
airlineCanonicalAliases[], facet, factValueText, rowId, routeScope, rowText, embeddingText, carryOnText, carryOnUrl,
carryOnUrlAliases[], carryOnCost, carryOnWeight, carryOnSize, carryOnNotes, firstBagUrl, secondBagUrl,
additionalPolicyUrl, firstBagUrlAliases[], secondBagUrlAliases[], additionalPolicyUrlAliases[]
```

## 5. Reliability: existing mechanisms and known gaps

### 5.1 Crawler side (deployed; do not change)
- Durable job, target, and result rows in PostgreSQL. Claims use `FOR UPDATE SKIP LOCKED`, a 60 s lease, and a 20 s heartbeat.
- **Recovery**: an expired lease means the job is reclaimed and its running targets are reset to `queued`. Each target gets at most 2 attempts. A 6 h job timeout fails any unfinished targets.
- **Duplicate prevention**: a deterministic result-key upsert ("success is sticky"); `requestId` plus payload-hash idempotency.
- **Limits**: a queue cap of 100 and 7-day retention. Webhook delivery is best-effort, at most 6 attempts.

### 5.2 Node side (EXISTING)

| Mechanism | Where | Notes |
|---|---|---|
| Idempotent job creation across retries | `Crawl4AIClient.requestJobApi` (same `requestId`) | POST is retried only on 5xx, network errors, and timeouts. |
| Polling with webhook wake-up | `ingestUrls` loop + `waitForCrawlJobSignal` / `notifyCrawlJob` | Polling is authoritative. A lost wake-up costs at most one poll delay (≤ 30 s). |
| Cursor-chain guard | `ingestUrls` | Throws on a repeated or missing cursor. |
| In-run alias dedupe | validation loop | `already_crawled_alias` → `skipped`. Shallowest depth wins. |
| Deterministic doc and point IDs | `crawl4ai-result.js`, `chunker.js`, `hybrid-documents.js` | Re-indexing overwrites the same points. |
| Upload, then prune | `ingestUrl` | Old points survive a failed upload. |
| Change detection | `contentHash` + fingerprint marker + Qdrant `hasRecords` | The marker is written only after Qdrant succeeds. A corrupt marker is a cache miss. |
| Per-document refresh lock | `index-refresh-lock.js` | In-process promise chain plus a cross-process file lock at `data/raw/.index-refresh-locks/<sha256>.lock`: `wx` create; stale when the PID is dead on the same host or the mtime is older than 15 min; 120 s wait timeout. |
| Page isolation | `mapWithConcurrency` + try/catch | One failing page never fails the job. |
| Webhook event dedupe | `IngestJobManager.seenCrawlEvents` | In memory only. |

### 5.3 Known gaps (EXISTING locally)
Do not silently "fix" these. List each one in your report, and propose a change only where it is cheap and clearly valuable.
- **G1. Ingest jobs live in memory.**
  - A Node restart loses job tracking and the in-flight wait. The crawler job still finishes, but its results are never indexed automatically and are deleted after 7 days.
  - Manual recovery exists: `scripts/index-existing-crawl-job.mjs --jobId=… --seedUrl=… --collection=… [--resume]`. But its idempotent lookup only works when the original job had **exactly one URL** (`requestId` plus payload hash); multi-URL jobs return 409.
- **G2. No overall wait timeout or cancellation.** If the crawler worker is down, the job stays `queued` and Node polls every 30 s indefinitely; the job manager passes no `AbortSignal`.
- **G3. A 429 (queue full) is not retried.** The ingest job fails.
- **G4. Untracked webhook events are ignored.** A webhook for a job Node isn't tracking is accepted and dropped, and `seenCrawlEvents` grows until restart.
- **G5. No retries around OpenAI or Qdrant calls inside `ingestUrl`.** A transient error fails that page with `indexing_error`. Re-running is safe because the marker was never written, but it starts a new crawl.
- **G6. No embedding batching.** Each document's embeddings go in a single request.
- **G7. A missing `OPENAI_API_KEY` is silent.** Pages report `ingested` without vectors (§4, step 11).
- **G8. Locks and markers are local to the filesystem.** Multiple Node instances must share `data/`, or ingestion must run on exactly one instance; otherwise concurrent refreshes of one document can interleave.
- **G9. All result items are held in memory.** Every result item for a job is loaded before indexing starts.
- **G10. Re-indexing always re-crawls.** No API indexes an existing completed crawler job; only the G1 script can.
- **G11. The directory URL must match exactly.** The crawler matches it after normalization, which keeps trailing slashes. `https://www.cheapoair.com/travel/baggage-fees` without the slash is crawled as a single `standard` page, while Node still treats it as the directory for enrichment. Submit the configured form, with the trailing slash.
- **G12. The new client needs a recent runtime.** It uses global `fetch`, `AbortSignal.timeout`, and, when a signal is passed, `AbortSignal.any`, which needs Node ≥ 20.3. Locally it runs on Node 24.15 with Express 5.2.1 and zod 4.3.6 installed (`package.json` declares `^5.2.1` and `^4.1.5`). Check production's Node, Express, and zod versions.

**Automated.** Production tests pass, plus the ported tests. For reference, the local baseline is **168 tests: 153 passed, 0 failed, 15 skipped** (the skipped ones are Docker-gated integration tests).

1. **Crawler connectivity and auth**: `GET /health` and `/ready` succeed. A wrong token produces a 401, which surfaces as a failed ingest job with a clear error.
2. **Single URL**: `POST /api/ingest {"urls":["https://www.cheapoair.com/info/service-fees/"],"collection":"<staging>"}`.

3. **Change detection and idempotency**:
   - Re-run the same request: a new crawler job runs and the page returns `skipped` with `content_hash_unchanged`.

   - Qdrant unavailable during indexing: affected pages fail with `indexing_error`, and earlier points remain.
   - Worker stopped: confirm G2 (Node keeps polling), then restore the worker.
8. **Retrieval regression** (read-only; no retrieval code changes): run production's existing retrieval and chat evaluations against the staging collection and compare with the current collection.

**Rollout.**
- Deploy the JS changes.
- Index into a new production collection and validate it.
- Switch `QDRANT_COLLECTION` (a configuration change only) once approved.
- Keep the previous collection.

**Rollback.**
- Point `QDRANT_COLLECTION` back to the previous collection and pause ingestion. Retrieval keeps working on the old collection.
- If production was on generation A, B, or C, rolling back the JS deployment does **not** restore crawling, because the deployed crawler no longer serves those endpoints.

---

## 12. Don'ts
- Don't modify retrieval or agent code, or the chat endpoints.
- Don't rewrite, reconfigure, or redeploy the Python crawler. Only report problems with it.
- Don't send `profile`, `maxDepth`, `policyKey`, `depth2AirlineCodes`, or any field other than `schemaVersion`, `requestId`, and `urls` to `POST /crawl/jobs`.
- Don't build or modify result cursors.
- Don't re-add Node-side crawling, child discovery, page retries, or URL batching.
- Don't make the webhook fetch results or start indexing. It only wakes the poller.
- Don't delete or overwrite Qdrant collections or `data/` artifacts.
- Don't change the Qdrant payload field names or meanings (§4.1).
- Don't commit secrets, or print them in logs or reports.

        reject(signal.reason || new DOMException("Aborted", "AbortError"));
        return;
      }
      const waiters = this.jobWaiters.get(jobId) || [];
      let timer;
      const finish = (reason) => {
        clearTimeout(timer);
        signal?.removeEventListener("abort", abort);
        resolve(reason);

        clearTimeout(timer);

function verifyCrawlWebhook({ rawBody, timestamp, signature, secret, now = Date.now() }) {
  if (!secret) {
    const error = new Error("Crawler webhook secret is not configured.");
    error.statusCode = 503;
    throw error;
  }
  if (!Buffer.isBuffer(rawBody) || !timestamp || !signature?.startsWith("v1=")) {
    const error = new Error("Invalid crawler webhook signature headers.");
    error.statusCode = 401;
    throw error;
  }
  const seconds = Number(timestamp);
  if (!Number.isInteger(seconds) || Math.abs(now - seconds * 1000) > 300_000) {
    const error = new Error("Crawler webhook timestamp is outside the replay window.");
    error.statusCode = 401;
    throw error;
  }
  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.`)
    .update(rawBody)
    .digest("hex");
  const supplied = signature.slice(3);
  const expectedBuffer = Buffer.from(expected, "hex");
  const suppliedBuffer = Buffer.from(supplied, "hex");
  if (expectedBuffer.length !== suppliedBuffer.length ||
    !timingSafeEqual(expectedBuffer, suppliedBuffer)) {
    const error = new Error("Invalid crawler webhook signature.");
    error.statusCode = 401;
    throw error;
  }
  return crawlWebhookEventSchema.parse(JSON.parse(rawBody.toString("utf8")));
}

```js
async function withIndexRefreshLock({ collection, docId, lockDir }, action) {
  const key = `${String(collection || "").trim()}:${String(docId || "").trim()}`;
  if (!collection || !docId) {
    throw new Error("Index refresh locking requires collection and docId.");
  }

  return withProcessLock(key, async () => {
    if (!lockDir) {
      return action();
    }

    const lockPath = join(lockDir, `${sha256(key)}.lock`);
    const releaseFileLock = await acquireFileLock(lockPath, { lockDir });
    try {
      return await action();
    } finally {
      await releaseFileLock();
    }
  });
}

export { withIndexRefreshLock };
```
`acquireFileLock` (lines 57–116) creates `<lockDir>/<sha256(collection:docId)>.lock` with flag `wx`, writing `{ token, pid, hostname, createdAt }`. An existing lock is removable when it belongs to this host and its PID is dead, or (for other hosts) when its mtime is older than 15 minutes. Acquisition polls every 100 ms and gives up after 120 s. Release deletes the file only if the token still matches.

export function crawlUrlIdentity(value, baseUrl) {
  try {
    if (typeof value !== "string" || !value.trim()) return null;
    const parsed = baseUrl ? new URL(value, baseUrl) : new URL(value);
    if (!["http:", "https:"].includes(parsed.protocol) || parsed.username || parsed.password) return null;
    return normalizeUrlForIdentity(parsed.toString());
  } catch {
    return null;
  }
}

export function isAirlineOwnedUrl(url, policy) {
  const normalized = crawlUrlIdentity(url);
  return Boolean(normalized && policy.allowedHostnames.includes(new URL(normalized).hostname));
}

export function resolveAirlineCrawlPolicy(target, policies) {
  const identities = [...new Set([
    target.airlineCanonical,
    ...(target.airlineCanonicalAliases || []),
  ].filter(Boolean))];

  if (identities.length) {
    const matches = identities.filter(
      (key) => policies[key] && isAirlineOwnedUrl(target.url, policies[key]),
    );
    return matches.length === 1 ? { key: matches[0], policy: policies[matches[0]] } : null;
  }

  const matches = Object.entries(policies).filter(
    ([, policy]) => isAirlineOwnedUrl(target.url, policy),
  );
  return matches.length === 1 ? { key: matches[0][0], policy: matches[0][1] } : null;

function normalizeForSearch(value) {
  return String(value || "")
    .toLowerCase()
    .replace(/[^a-z0-9]+/gu, " ")
    .trim();

    .split(/\s+/u)
    .filter(Boolean);

  const originalTokens = tokenize(value).filter((token) => token !== "the");
  if (!originalTokens.length) {

def _post(url: str, secret: str, payload: dict[str, Any]) -> None:
    raw = json.dumps(payload, separators=(",", ":")).encode("utf-8")
    timestamp = str(int(time.time()))
    signature = hmac.new(
        secret.encode("utf-8"),
        timestamp.encode("ascii") + b"." + raw,
        hashlib.sha256,
    ).hexdigest()
    outgoing = request.Request(
        url,
        data=raw,
        method="POST",
        headers={
            "content-type": "application/json",
            "x-crawl-timestamp": timestamp,
            "x-crawl-signature": f"v1={signature}",
        },
    )
    with request.urlopen(outgoing, timeout=15) as response:
        if response.status < 200 or response.status >= 300:
            raise RuntimeError(f"Webhook returned HTTP {response.status}.")


async def deliver_due_webhooks(repository) -> None:
    url = os.getenv("CRAWL_COMPLETION_WEBHOOK_URL", "").strip()
    secret = os.getenv("CRAWL_WEBHOOK_SECRET", "")
    if not url:
        return
    if not secret:
        raise RuntimeError("CRAWL_WEBHOOK_SECRET is required when webhook URL is configured.")

    for job in await repository.webhook_jobs_due():
        status = await repository.get_job_status(job["id"])
        if status is None:
            continue
        attempt_index = min(int(job["webhook_attempts"]), len(DELAYS_SECONDS) - 1)
        try:
            await asyncio.to_thread(_post, url, secret, terminal_event(status))
            await repository.record_webhook_attempt(
                job["id"], delivered=True, error=None, delay_seconds=None
            )
        except Exception as error:  # delivery is best effort; polling stays authoritative
            next_delay = DELAYS_SECONDS[attempt_index]
            await repository.record_webhook_attempt(
                job["id"],
                delivered=False,
                error=str(error)[:1_000],
                delay_seconds=next_delay,
