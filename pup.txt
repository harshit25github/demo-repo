Debug Flight Agent Conversation History Usage

Flight Agent is relying too heavily on dynamically hydrated context. When that context is empty, it sometimes ignores useful information already present in the OpenAI conversation/session history.

Please inspect:

whether conversationId / session history is actually being passed and restored correctly
what history Flight Agent receives at runtime
whether prompt rules are causing dynamic context to override/ignore conversation history
whether earlier user-provided route, dates, passengers, cabin, etc. can be reused when current context is missing

Expected priority:
current user message > current hydrated context/searchCriteria > relevant conversation history > defaults

Find the root cause and propose the minimal fix before implementing.
