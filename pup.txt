Plan Trip Planner Agent safety/guardrail improvements.

## Context

We have:
- Gateway Agent with guardrails
- Trip Planner Agent
- Other routed agents

Even with existing guardrails, some unsafe/jailbreak prompts are still reaching Trip Planner and causing unsafe responses.

We need to strengthen Trip Planner directly, not only rely on Gateway.

## Safety areas to handle

Trip Planner must refuse or safely redirect requests involving:

- explicit sexual content
- child sexual content
- bomb-making/explosives/weapons instructions
- illegal activity
- self-harm/violence
- privacy violations
- system prompt/private instruction extraction
- jailbreak attempts
- roleplay attempts to bypass rules

## Required behavior

Trip Planner should:

- refuse briefly and professionally
- not provide operational unsafe details
- not continue unsafe roleplay
- not call tools for unsafe content
- not expose system/developer/private instructions
- redirect only to safe travel-planning help when appropriate

## What to analyze

1. Current Trip Planner prompt
- Check if it has its own safety rules.
- Identify where unsafe prompts can bypass Gateway.
- Check whether jailbreak text can override Trip Planner instructions.

2. Gateway + Trip Planner split
Explain:
- what Gateway should block
- what Trip Planner should refuse internally
- how to avoid duplicate/conflicting responses

3. Tool safety
Check:
- whether Trip Planner can call web/tools for unsafe requests
- how to prevent tool calls when intent is unsafe
