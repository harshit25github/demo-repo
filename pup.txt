Fix Extractor Agent `suggestedQuestions` logic using `currentAgent` and `searchKey`.

Context:
Currently, after every agentic workflow completes, we call the Extractor Agent with:
- old summary context
- current user message
- current assistant/agent response

Extractor Agent updates the summary object and generates `suggestedQuestions`.

Problem:
The Extractor Agent does not know:
1. Which agent was triggered in the current turn.
2. Whether Flight Agent already has a valid flight search context/search key.

Because of this, it sometimes generates wrong suggestions for Flight Agent, like:
- asking the agent to pick origin/destination/date
- showing advanced filter questions before flight results exist
- repeating stale suggestions from previous turns

## Solution

Enhance the Extractor Agent input payload by passing two additional fields:

```ts
currentAgent: string
searchKey?: string | null
````

So the Extractor Agent input should become:

```ts
{
  oldSummaryContext,
  currentUserMessage,
  currentAgentResponse,
  currentAgent,
  searchKey
}
```

Where:

* `currentAgent` = last/current agent triggered by the workflow, e.g. `flight`, `tripPlanner`, `policy`
* `searchKey` = flight search key if a flight search has already happened
* If no flight search exists, `searchKey` should be `null` or empty

Implementation requirements:

1. Update workflow/extractor call

* Wherever Extractor Agent is called after the main agent response, pass:

  * `currentAgent`
  * `searchKey`
* `currentAgent` should come from the last triggered agent in the workflow.
* `searchKey` should come from current flight context/search criteria if available.

2. Update Extractor Agent input schema

* Add `currentAgent`
* Add optional `searchKey`
* Keep existing fields unchanged.

3. Update Extractor Agent prompt/logic

If `currentAgent` is Flight Agent:

A. Never suggest questions where the agent is asked to choose/provide:

* origin
* destination
* travel date/date range

Blocked examples:

* "Pick a destination for me"
* "Suggest where I should fly"
* "Choose my travel dates"
* "Suggest a departure city"
* "When should I travel?"
* "Find me a destination"

These fields must always come from the user.

B. Only suggest advanced flight filters if `searchKey` exists.

If `searchKey` does NOT exist, do not suggest:

* "Apply non-stop filter"
* "Show morning departures"
* "Show flights with checked baggage"
* "Compare current options"
* "Which flight is best?"
* "Show cheaper flights"
* "Show United Airlines flights"

Safe suggestions when Flight Agent is active but `searchKey` does NOT exist:

* "Update cabin to economy"
* "Update cabin to premium economy"
* "Change trip type to round trip"
* "Search one-way flights"
* "Add 2 adults"
* "Change passenger count"

Allowed suggestions when Flight Agent is active and `searchKey` exists:

* "Show cheaper flights"
* "Apply non-stop filter"
* "Show morning departures"
* "Show flights with checked baggage"
* "Compare current options"
* "Which flight is best?"
* "Show United Airlines flights"
* "Show flights with shorter layover"

4. General suggestion rules

* `suggestedQuestions` must always be from the user’s perspective.
* Do not generate assistant-style questions like:

  * "Would you like..."
  * "Do you want..."
  * "Should I..."
  * "When are you..."
* Prefer user-style actions:

  * "Show..."
  * "Apply..."
  * "Compare..."
  * "Update..."
  * "Change..."
  * "Add..."
  * "Search..."

5. Avoid repetition

* Do not blindly reuse old `suggestedQuestions`.
* Current user message + current agent response should drive the latest suggestions.
* Old summary context should be used only for continuity.
* Avoid repeating same/similar suggestions across turns.

Tests to add:

1. Flight Agent active + no `searchKey`

   * should not generate advanced filter/result suggestions.

2. Flight Agent active + valid `searchKey`

   * can generate advanced filter/result suggestions.

3. Flight Agent active with missing origin/destination/date

   * should not suggest agent-side questions like “pick destination” or “choose travel date”.

4. Non-Flight Agent active

   * existing behavior should remain stable.

5. Multi-turn flow

   * suggestions should refresh and avoid repeated stale questions.

Deliverable:

* Add `currentAgent` and `searchKey` to Extractor Agent input.
* Update schema and prompt/logic.
* Add tests for Flight Agent suggestion rules.
* Provide a short report:

  * files changed
  * how `currentAgent` and `searchKey` are passed
  * before/after examples
  * test results
