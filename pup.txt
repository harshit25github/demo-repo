Plan Flight Agent applied-filter context for suggested questions.

Do not implement yet. First inspect current flow and propose the cleanest plan.

## Problem

When user applies a filter during flight search, the same filter should not appear again in “You might ask” / suggested questions.

Example:
User: “Delhi to Mumbai on 12 August, only morning flights.”

Flow:
- `flight_search_tool` runs.
- `apply_filter_tool` applies morning filter.
- Morning filter is now active.
- Suggested questions should not include:
  - “Show me morning flights”
  - “Filter by morning departure”
  - or any duplicate already-applied filter suggestion.

## Goal

Track applied filters in Flight Agent context and expose them in dynamic prompt so the agent avoids generating suggested questions for filters already applied.

## Required behavior

### 1. Store applied filters after apply_filter

Whenever `apply_filter_tool` successfully applies filters:
- capture the array/list of applied filters
- store it in Flight context

Example shape can be planned as:

```ts
context.flight.appliedFilters = [
  {
    filterType: "departtimeslotfilter",
    values: ["morning"],
    label: "Morning flights"
  }
]
````

Use existing context style if a better structure already exists.

### 2. Reset applied filters on new search

Whenever a new flight search is initiated and a new `searchKey` is created:

* reset applied filters to empty array
* avoid carrying filters from old searchKey to new search

Expected:

```ts
context.flight.appliedFilters = []
```

### 3. Dynamic prompt hydration

When Flight Agent dynamic prompt is created:

* include compact applied filter summary
* clearly tell agent these filters are already active
* tell agent not to generate suggested questions for already-applied filters

Example dynamic prompt data:

```txt
Already applied filters:
- Morning flights
- Non-stop
- Emirates

Do not suggest these same filters again in suggested questions.
```

### 4. Suggested questions behavior

Update Flight Agent suggested question instructions so:

* suggestions must not repeat active filters
* suggestions should focus on useful next actions not already applied
* if all common filters are applied, suggest result reasoning or alternative useful actions instead

Good:

* “Show me the cheapest option”
* “Compare the top 3 flights”
* “Show shorter-duration options”

Bad if already applied:

* “Show morning flights”
* “Apply morning filter”
* “Only show non-stop flights”

## Important rules

* Do not change tool schemas unless required.
* Do not modify unrelated agents.
* Do not change apply-filter API contract.
* Keep applied filter context compact.
* Do not store huge filter response payloads.
* Reset filters only when new search/searchKey happens.
* Preserve filters across pure follow-up turns for the same searchKey.
