Implement a small update to the existing “new chat creation” flow.

Current behavior:
When a user sends their first request, if there is no `chatId`, we treat it as a new chat. The API creates a new chat, generates a title, and saves it to the chat storage tables.

New requirement:
We now also need to store an emoji alongside the generated chat title.

Context:
The emoji generation/selection logic is already handled. Your task is to integrate the improved agent/output into the existing API flow so that the emoji is persisted together with the title when a new chat is created.

What to implement:

1. Find the API path that handles the first user request when `chatId` is missing.
2. Locate where the new chat is created, titled, and saved.
3. Update that flow so the generated emoji is included alongside the title.
4. Ensure the relevant chat storage tables are updated with the emoji value.
5. Preserve all existing behavior for title generation, chat creation, and message handling.
6. Add or update tests to verify:

   * A new chat without `chatId` creates a title and emoji.
   * The emoji is saved in the correct chat storage table/field.
   * Existing chats with a `chatId` are not accidentally retitled or re-emoji’d.
   * The flow still works if emoji generation returns empty/null, using the agreed fallback behavior.

Acceptance criteria:

* New chats store both `title` and `emoji`.
* Existing chats continue working unchanged.
* No duplicate chat creation.
* No breaking changes to the API response shape unless required.
* Tests cover the new persistence behavior.
