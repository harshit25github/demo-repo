Task: Fix the `Get Generated Context` tool for flight search follow-up questions.

Background:
We have two tools:

1. `Flight Search Tool`
   - Runs the flight search.
   - Returns flight options to the user.
   - Saves the generated flight search context.

2. `Get Generated Context`
   - Used when the user asks follow-up questions.
   - Examples:
     - “Compare option 1 and option 4”
     - “Which flight is cheapest?”
     - “Which one is fastest?”
     - “Which option has the shortest layover?”

Problem:
`Get Generated Context` is not passing the complete saved context to the answering agent.
Some important fields appear to be missing, renamed, flattened, or summarized away.
Because of this, the agent cannot reliably compare flight options.

I will provide an example of the saved context below:

[PASTE CONTEXT EXAMPLE HERE]

Your job:
Inspect how the flight context is saved and how `Get Generated Context` retrieves/formats it.

Fix `Get Generated Context` so it returns a complete, structured, agent-friendly context.

Requirements:

1. Preserve important flight data
Each flight option should include, when available:
- option number / option ID
- airline name
- flight number
- departure airport
- arrival airport
- departure time
- arrival time
- total duration
- number of stops
- layover airport and duration
- price and currency
- cabin / fare class
- baggage details
- refund/cancellation details
- provider/booking metadata
- warnings or notes

2. Preserve search-level data
Include original search details:
- origin
- destination
- departure date
- return date, if any
- trip type
- passenger count
- cabin class
- user filters/preferences

3. Avoid lossy summarization
Do not return only a prose summary.
The answering agent needs structured data for reasoning.

A short summary is fine, but the full structured context must also be included.

4. Keep option references stable
If the user says “option 1” or “option 4”, the agent must be able to map those references exactly to the correct flight options.

Do not reorder or renumber options unless there is a clear mapping.

5. Preserve raw context
Return both:
- normalized context for easy reasoning
- raw/original context to avoid losing provider-specific fields
