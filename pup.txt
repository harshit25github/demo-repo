Task:
Analyze and plan the best approach for updating the Human Handoff flow.

Context:
We currently have a Human Handoff Guardrail in the Gateway workflow.
Earlier, this flow was confirmation-based:
- user asks for human agent
- system asks for confirmation
- later confirmation triggers handoff

Now the requirement has changed:
- we should not ask for confirmation
- we should show a soft denial message instead
- if the user asks for a human agent again later, we should show the same soft denial again

The soft denial message already exists in the code.

Your Task:
Do not implement directly.

First, inspect the codebase and provide the best plan to handle this change.

Please analyze:
- where Human Handoff Guardrail is implemented
- where confirmation state is stored
- where approval-check logic runs before runner
- where final handoff/tripwire is triggered
- where soft denial message should be returned
- how to safely remove/disable old confirmation logic
- how to make repeated human-agent requests return soft denial
- how to avoid breaking existing guardrails and routing

Expected Output:
Provide a simple implementation plan with:
- files/functions to update
- old logic to remove/disable
- new flow proposal
- edge cases
- test cases
- risks

Goal:
Find the cleanest and safest way to move from confirmation-based human handoff to soft-denial-based human handoff.
