Task:
Enhance Human Handoff confirmation flow to support delayed confirmation.

Context:
Currently, when Human Handoff Guardrail triggers for the first time, we save a DB attribute and ask user for confirmation.
Before the next runner call, we run a checker agent to verify if the user approved human handoff.

Change Required:
The user may not confirm in the immediate next turn.
They may continue normal conversation and confirm human handoff later at any point.

Required Behavior:
- When human handoff is requested first time, save pending handoff state in DB/context.
- Continue normal workflow after asking confirmation.
- Do not assume confirmation must come in the next message.
- On every future user message, check if human handoff confirmation is pending.
- If user clearly confirms human handoff later, trigger final handoff.
- If user cancels, clear pending handoff state.
- If user asks unrelated queries, continue normal workflow but keep pending state active.

Important Rule:
Avoid accidental confirmation.
- If confirmation is immediate next reply, short replies like “yes”, “haan”, “ok” can confirm.
- If confirmation comes after unrelated turns, require clear intent like:
  - “yes connect me to human”
  - “connect me to agent”
  - “I still want human support”
  - “talk to real person”

DB/Context State:
Use something like:
humanHandoffStatus = "pending" | "confirmed" | "cancelled" | null

Acceptance Criteria:
- Pending handoff remains active across multiple turns.
- Confirmation can happen anytime later in the flow.
- Unrelated messages do not clear pending state.
- Generic “yes” does not accidentally trigger handoff after unrelated turns.
- Cancel messages clear pending state.
- Final handoff triggers only after clear confirmation.
