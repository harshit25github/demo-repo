# Plan Streaming Events and Abort Timeout Handling

Plan the streaming enhancement first. Do not implement yet.

## Goal

Our OpenAI SDK streaming flow currently handles:

* `data`
* `error`
* `end`

Add support for three more stream events:

* `close`
* `pause`
* `resume`

Also handle AbortController timeout clearly.

## Requirements

### 1. Stream event chunks

When these events occur, send a proper server-side chunk to the client:

```json
{ "status": "stream_closed", "message": "Stream closed." }
{ "status": "stream_paused", "message": "Stream paused." }
{ "status": "stream_resumed", "message": "Stream resumed." }
```

### 2. Abort timeout handling

We already have AbortController with a 2-minute timeout.

When abort happens due to timeout/idleness:

* detect it properly
* send a clear chunk to client
* avoid generic error messaging

Example:

```json
{
  "status": "timeout_aborted",
  "message": "Request was aborted because the stream was idle for 2 minutes."
}
```

### 3. Safety

Plan how to:

* avoid duplicate final chunks
* avoid writing after response is closed
* clean up timers/listeners
* distinguish normal close vs timeout abort
* log each event clearly

## What to inspect

* current OpenAI stream handler
* data/error event handling
* AbortController timeout logic
* response chunk writer
* stream cleanup/finalization flow

## Deliverable

Provide a short plan with:

1. Current streaming flow

3. Abort timeout detection plan

7. Risks and safeguards
8. Step-by-step implementation plan
