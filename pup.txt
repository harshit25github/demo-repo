# Fix Origin/Destination Field Separation in Flight Agent

Review the Flight Agent prompt and `flight_search` tool schema/field descriptions. Fix the location mapping so **city/location name and airport/IATA information are never combined into the same field**.

Example current wrong call:

```ts
destination: "London LHR"
destination_iata: "LHR"
destination_airport_name: "London Heathrow Airport"
```

Expected:

```ts
destination: "London"
destination_iata: "LHR"
destination_airport_name: "London Heathrow Airport"
```

Apply the same rule to **origin** as well:

* `origin` / `destination` → city or location name only
* `origin_iata` / `destination_iata` → IATA code only
* `origin_airport_name` / `destination_airport_name` → airport name only

If user says `"Delhi to London LHR"`, interpret `"London"` as the destination and `"LHR"` as the airport constraint/code. Never generate values such as `"London LHR"`, `"Delhi DEL"`, or multiple locations inside a single location field.

Update both:

1. Flight Agent prompt/instructions
2. Tool payload schema descriptions/examples

Keep the fix general, minimal, and consistent across origin and destination. Add tests for city-only, city + IATA, airport-name + IATA, and both origin/destination combinations to ensure this does not regress.
