Fix Trip Planner streaming response to remove links before sending chunks to client.

Context:

* We have a gateway/agentic workflow with multiple agents.
* During OpenAI streaming, we can identify the active/last triggered agent using `last_agent`.
* This fix is only required when `last_agent` is Trip Planner.
* Trip Planner sometimes generates links/source URLs in streamed text chunks.
* We do not want to show any links in Trip Planner responses on the client side.

Required handling:
Add a server-side sanitization layer for Trip Planner streamed chunks.

Goals:

1. Update Trip Planner prompt so it does not generate links in the response.
2. Sanitize streaming chunks before sending them to the client.
3. Sanitize the final accumulated response before sending the final `status: done` payload.

Streaming behavior:

* If `last_agent` is not Trip Planner, keep existing streaming behavior unchanged.
* If `last_agent` is Trip Planner:

  * Do not directly forward raw chunks to client.
  * Buffer chunks safely before sending.
  * Detect and remove links from the buffered text.
  * Handle links even when they are split across multiple chunks.
  * Send only sanitized text to the client.

Links to remove:

* Raw URLs:

  * `https://...`
  * `http://...`
  * `www.example.com`
* Markdown links:

  * `[text](https://...)`
* HTML links:

  * `<a href="...">text</a>`
* Source/reference style links if generated in text.

Important:
Chunks can be very small, so a link may be split like:

* chunk 1: `Visit https://`
* chunk 2: `example.com for details`

In this case:

* Buffer until the link is complete.
* Remove the full link.
* Then send the cleaned text.

Suggested approach:

* Create a Trip Planner stream sanitizer utility.
* Maintain a small rolling buffer for Trip Planner chunks.
* Flush only safe/sanitized text.
* Keep enough trailing characters in buffer to detect incomplete URLs/markdown links.
* On stream completion, flush the remaining sanitized buffer.
* Also sanitize the final accumulated response before sending `status: done`.

Final response handling:

* We already maintain a variable that accumulates the full streamed response.
* Before sending the final `status: done` response:

  * validate the full text
  * remove any remaining links
  * send only sanitized final text

Trip Planner prompt update:
Add/strengthen instruction:

* Do not include raw URLs.
* Do not include markdown links.
* Do not include source links.
* Mention places/recommendations naturally without clickable links.

Tests to add:

1. Trip Planner returns raw URL in one chunk → link removed before client receives it.
2. Trip Planner URL split across multiple chunks → full link removed.
3. Markdown link split across chunks → link removed, visible text preserved if possible.
4. HTML anchor link → link removed.
5. Final accumulated response contains link → removed before `status: done`.
6. Non-Trip Planner agent response contains normal text → streaming unchanged.
7. Trip Planner response without links → streaming should work normally.
8. No broken/incomplete chunks should be sent to client.

Deliverable:

* Implement Trip Planner-only link sanitization for streaming chunks.
* Update Trip Planner prompt to avoid links.
* Add final response sanitization before `status: done`.
* Add tests for split-link streaming cases.
* Provide a short report:

  * root cause
  * implementation approach
  * before/after examples
  * test results
