# Task: Fix Airline Retrieval Agent Comparisons and Simplify Responses

We have two problems in our airline retrieval service:

1. Comparison answers are inconsistent.
2. Airline explanations are too complicated for regular users.

## Problem 1: Comparison Queries Are Weak/Inconsistent

Example queries:

- Compare Emirates and Qatar Airways
- Which is better, Delta or United for baggage?
- Compare Singapore Airlines, Emirates, and Qatar for long-haul economy
- Is Turkish Airlines better than Lufthansa for cancellation flexibility?

Current issue:

The agent sometimes receives uneven or incomplete data, so it gives inconsistent comparison results.

## Required Fix: Comparison-Specific Retrieval Flow

Implement this flow:

1. Detect when the user is asking for a comparison.
2. Extract airline names from the query.
3. Extract requested comparison topics, such as:
   - baggage
   - cancellation
   - refunds
   - seat comfort
   - fees
   - routes
   - customer service
   - loyalty program
   - on-time performance
4. Retrieve data separately for each airline.
5. If topics are mentioned, retrieve separately for each airline and each topic.
6. Make sure evidence is balanced before calling the agent.
7. If one airline has weak or missing data, run a fallback retrieval pass.
8. Pass a structured comparison context to the agent instead of raw chunks.
9. The agent must not guess when data is missing.

## Example Comparison Context

Use a structure like this:

{
  "airlines": ["Emirates", "Qatar Airways"],
  "dimensions": {
    "baggage_policy": {
      "Emirates": {
        "summary": "Economy baggage allowance depends on fare type and route.",
        "evidence": ["chunk_id_1"],
        "confidence": "medium"
      },
      "Qatar Airways": {
        "summary": "Economy baggage allowance depends on route and fare family.",
        "evidence": ["chunk_id_2"],
        "confidence": "medium"
      }
    }
  },
  "missing_data": []
}

## Problem 2: Responses Are Too Complicated

Current issue:

The agent explains airline details in a technical way that regular travelers may not understand.

## Required Fix: Plain-Language Response Layer

Add a final response layer that converts retrieved/reasoned data into simple traveler-friendly language.

Final answers should be:

- Simple
- Short
- Practical
- Easy to understand
- Focused only on what matters to the traveler
- Free from airline industry jargon
- Honest when details depend on route, fare type, cabin class, or travel date
- Clear when data is missing

## Default Format for Comparison Answers

Use this format:

Quick verdict:
Give a short, clear summary.

Key differences:
Compare only the most important points.

Best for:
Mention which airline is better for which traveler need.

Things to double-check before booking:
Mention fare rules, baggage, cancellation, refunds, and route-specific details if relevant.

## Indexing Improvements

Review and improve the airline index.

Each chunk should be topic-specific and include metadata like:

{
  "airline_name": "Qatar Airways",
  "airline_code": "QR",
  "topic": "baggage_policy",
  "cabin": "economy",
  "region": "global",
  "content": "...",
  "source_url": "...",
  "last_updated": "..."
}

Recommended topics:

- baggage_policy
- cancellation_policy
- refund_policy
- seat_comfort
- fees
- routes
- loyalty_program
- customer_service
- on_time_performance
- economy_experience
- business_class
- family_travel
- accessibility

## Airline Alias Handling

Support aliases such as:

- Qatar = Qatar Airways
- Emirates = Emirates Airline
- Singapore = Singapore Airlines
- Turkish = Turkish Airlines
- Lufthansa = Lufthansa German Airlines
- Delta = Delta Air Lines
- United = United Airlines

## Guardrails

The agent must follow these rules:

- Compare only using retrieved evidence.
- Do not guess missing details.
- If data is missing for one airline, say so clearly.
- Do not over-explain.
- Do not expose internal chunk IDs, metadata, embeddings, or retrieval logic to the user.
- Keep final answers simple and useful.

## Acceptance Criteria

The fix is successful when:

- Comparison queries retrieve balanced evidence for each airline.
- The agent receives structured comparison context, not messy raw chunks.
- Missing data is clearly reported.
- Airline aliases work correctly.
- Final answers are short, simple, and traveler-friendly.
- The agent does not invent or assume policy details.
- Tests pass for these queries:
  - Compare Emirates and Qatar Airways
  - Which is better, Delta or United for baggage?
  - Compare Singapore Airlines, Emirates, and Qatar for long-haul economy
  - Is Turkish Airlines better than Lufthansa for cancellation flexibility?
