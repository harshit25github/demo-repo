Task:
Update Human Handoff flow from confirmation-based flow to soft-denial flow.

Context:
Previously, when Human Handoff Guardrail triggered, we asked the user for confirmation and saved a DB/context attribute to check if the user approved handoff later.

New Change:
We are no longer taking confirmation from the user.
Instead, when the user asks to connect with a human agent, we show a soft denial message.

Note:
The soft denial message is already added in the code. Use that existing message.

Required Behavior:
- If user asks for a human agent/support/real person, trigger Human Handoff Guardrail.
- Do not ask for confirmation.
- Do not wait for user approval in the next turn.
- Do not run approval-check logic before runner.
- Return the existing soft denial message.
- If the user asks for a human agent again at any later point in the conversation, return the same soft denial response again.
- Do not route this request to Trip Planner, Flight, or Policy agents.
- Do not expose guardrail, tripwire, DB, or internal workflow details to the user.

Remove/Disable:
- confirmation pending logic
- confirmation approval checker agent
- “yes/haan/ok” confirmation handling
- delayed confirmation logic
- final handoff trigger based on user confirmation

Acceptance Criteria:
- First human agent request returns soft denial message.
- Later human agent requests also return soft denial message.
- No confirmation is asked.
- No final handoff is triggered from confirmation.
- Existing non-human queries continue normal routing.
