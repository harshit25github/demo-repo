### New Trigger Rule

Trigger **post-booking intent** when the user message contains only booking-identification information, such as:

* booking number
* PNR
* confirmation/reference number
* any numeric/alphanumeric identifier that is clearly linked to an existing booking

Examples:

`ABCD12` → Post-booking
`PNR 6E4XYZ` → Post-booking
`Booking 12345678` → Post-booking
`12345678` → Post-booking **only when context indicates this is a booking/reference number**

### Important

* Do not require an explicit action like `"cancel"`, `"change"`, or `"refund"`.
* A booking identifier alone is enough when it clearly refers to an existing booking.
* Use current message + conversation history/context to determine whether a bare number is booking-related.
* Do not classify arbitrary numbers as post-booking without supporting context.
