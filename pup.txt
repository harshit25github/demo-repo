Enhance **location ambiguity handling in the Flight Agent** for both **Gateway V1 and Manager V2**.

### Requirements

1. **Destination API Validation**
   - When a user provides a location, use our existing Destination API within the Flight Search tool to resolve valid destinations and airports.
   - Use the tool's actual feedback instead of relying solely on LLM assumptions.

2. **Intelligent Location Clarification**
   - If multiple plausible locations or airports are returned, present relevant options and ask the user to select.
   - Example: "Paraguay" → Retrieve available airports/cities in Paraguay and offer valid choices instead of simply asking "Where in Paraguay?"
   - Handle misspellings, ambiguous city names, and country-level destinations intelligently.
   - Avoid unnecessary clarification when the location is already clear and supported.

3. **Preserve Flight Search Rules**
   - Destination lookup must not initiate a flight search prematurely.
   - Continue requiring a confirmed trip type before executing `flight_search`.
   - Preserve confirmed locations and search criteria across turns.

4. **Implementation & Testing**
   - Inspect the existing Destination API and its response structure.
   - Apply consistent behavior across Gateway and Manager.
   - Test ambiguous locations, multiple airports, country-level queries, misspellings, and follow-up selections.
   - Ensure tool feedback is properly communicated to users.

**Goal:** Use real destination data to provide accurate, selectable location options rather than making assumptions or asking vague clarification questions.

Keep changes minimal and reuse existing tools and logic.
