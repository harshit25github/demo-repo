```markdown
Fix Flight Agent `suggestedQuestions` generation in Extractor Agent.

Context:
- After every agent workflow, Extractor Agent runs.
- It receives:
  - current user message
  - current agent response
  - older summary context
- It updates the summary object and returns `suggestedQuestions: string[]`.
- These suggestions are shown in UI as “You might ask”.
- These should always be user-side queries/actions, not questions from agent to user.

We need to fix two issues together for Flight Agent flows.

Issue 1: Mandatory flight search fields should not be suggested
Flight Agent has 3 mandatory fields:
- origin
- destination
- travel date/date range

These values must always come from the user directly. The agent should not recommend/pick these values through suggested questions.

Blocked suggestions:
- "Pick a destination for me"
- "Suggest where I should fly"
- "Choose my travel dates"
- "Suggest a departure city"
- "Where should I travel?"
- "Find me a destination"
- "When should I travel?"

Do not generate suggested questions related to choosing/recommending:
- origin
- destination
- travel dates

Issue 2: Advanced filters should only appear after search exists
Advanced flight suggestions should only be generated if:

`context.flight.search_key` exists

`search_key` means flight search already happened and we have filterable/searchable context.

If `context.flight.search_key` does NOT exist:
Do not suggest:
- "Show morning departures"
- "Show flights with checked baggage"
- "Apply non-stop filter"
- "Compare current options"
- "Which flight is best?"
- "Show cheaper flights"
- "Show United Airlines flights"
- "Show shorter layovers"

Because these only make sense after flight results exist.

Safe suggestions when `search_key` does NOT exist:
- "Update cabin to economy"
- "Update cabin to premium economy"
- "Change trip type to round trip"
- "Search one-way flights"
- "Add 2 adults"
- "Change passenger count"
- "Add 1 child"

Allowed suggestions when `search_key` exists:
- "Show cheaper flights"
- "Apply non-stop filter"
- "Show morning departures"
- "Show flights with checked baggage"
- "Compare current options"
- "Which flight is best?"
- "Show United Airlines flights"
- "Show flights with shorter layover"

General rules:
- Suggestions must be from the user’s perspective.
- Do not write assistant-style questions like:
  - "Would you like..."
  - "Do you want..."
  - "Should I..."
  - "When are you..."
- Prefer user-style actions:
  - "Update..."
  - "Add..."
  - "Change..."
  - "Show..."
  - "Apply..."
  - "Compare..."
  - "Search..."

Also fix repetition:
- Do not repeat the same suggestions across turns.
- Current user message + current agent response should drive suggestions.
- Older summary context should only be used for continuity.
- Avoid stale suggestions from previous turns.

Required implementation:
- Add Flight Agent specific rules in Extractor Agent prompt/logic.
- Add gating condition for advanced suggestions using `context.flight.search_key`.
- Add blocking rules for origin/destination/travel-date suggestions.
- Keep output format as `suggestedQuestions: string[]`.

Test cases:
1. Flight Agent active, no `context.flight.search_key`:
   - only safe suggestions like cabin, trip type, passengers.
   - no filters/result comparison suggestions.

2. Flight Agent active, `context.flight.search_key` exists:
   - advanced filters and result comparison suggestions are allowed.

3. Flight Agent missing origin/destination/date:
   - suggestedQuestions must still not ask agent to pick/suggest these fields.

4. Multiple turns:
   - suggestions should refresh and avoid repetition.

Deliverable:
- Fix Extractor Agent suggestion logic.
- Add tests.
- Provide before/after examples.
- Provide short report with root cause, changes made, and test results.
```
