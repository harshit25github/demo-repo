We have two workbooks/environments in the backend:

1. Desktop workbook
2. Mobile workbook

Until now, the agent enhancement work has been focused on the desktop workbook. After the current desktop enhancement is completed, please analyze and prepare the equivalent changes for the mobile workbook/mobile agent setup.

Your task is to whiteboard the mobile-side implementation plan before code changes are made.

Please review the mobile workbook architecture, mobile agent configuration, prompts, model declarations, guardrails, routing logic, schemas, and tests. Compare them with the updated desktop implementation and identify what needs to be replicated, adapted, or handled differently for mobile.

Scope for mobile workbook:

1. Planner Agent
- Check whether the mobile planner agent uses the same planner prompt/config as desktop or has a separate mobile-specific version.
- If the planner agent model has also been moved to GPT-5.5, verify compatibility.
- Identify whether any prompt, schema, tool-calling, or response-format changes are needed for GPT-5.5.
- If no changes are required, clearly mention that.

2. Gateway Agent
- Identify the current model used by the mobile gateway agent.
- If it is still using Sofa 1.1 or an older model, plan its migration to GPT-5.4.
- Convert or adapt the gateway prompt so it is compatible with GPT-5.4.
- Preserve mobile-specific routing behavior, classification behavior, and tool-selection logic.
- Ensure the mobile gateway continues to route correctly between agents, including the new flight agent.

3. Unified Input Guardrail Agent
- Review how the mobile workbook uses the unified input guardrail.
- Check whether valid flight-agent queries are being incorrectly blocked on mobile, especially:
  - flight comparison queries,
  - fare comparison queries,
  - airline comparison queries,
  - route comparison queries,
  - booking-preference comparison queries,
  - normal travel-planning queries.
- Plan prompt updates so these legitimate flight-related requests are allowed.
- The guardrail should still block genuinely unsafe, abusive, fraudulent, disallowed, or policy-violating requests.
- Include mobile-specific examples if mobile user queries are shorter, more conversational, or more ambiguous.

4. Post-Booking Guardrail Agent
- Identify the current model used by the mobile post-booking guardrail.
- If it is on GPT-4.1 nano, plan migration to GPT-5.4 nano.
- Adapt the prompt so it is concise, deterministic, and understandable by GPT-5.4 nano.
- Preserve the existing post-booking safety behavior while reducing false positives.

5. Desktop-to-Mobile Parity
- Compare the completed desktop changes with the mobile workbook.
- Identify which changes can be copied directly.
- Identify which changes need mobile-specific adaptation.
- Do not blindly copy desktop prompts if mobile has different routing, UX, response expectations, or schema behavior.
- Preserve all existing mobile API contracts, schemas, response formats, and tool interfaces.

6. Testing Plan
Please propose targeted tests for the mobile workbook, including:
- valid flight search queries,
- valid flight comparison queries,
- valid fare/airline/route comparison queries,
- post-booking safe queries,
- post-booking unsafe or invalid queries,
- gateway routing tests,
- guardrail false-positive regression tests,
- model compatibility tests for GPT-5.4, GPT-5.4 nano, and GPT-5.5 where applicable.

Expected whiteboard output:
- Summary of current mobile agent setup.
- Gap analysis between desktop and mobile.
- Exact mobile agents that need model changes.
- Exact prompts that need conversion or cleanup.
- Risk areas and compatibility concerns.
- Suggested implementation order.
- Suggested test cases.
- Any places where desktop logic should not be copied directly.
- Final checklist for the microeditor before implementation.

Important:
- This is a planning/whiteboarding task, not a blind implementation.
- Keep changes minimal and focused.
- Preserve mobile-specific behavior.
- Maintain parity with desktop only where appropriate.
- Make sure the mobile workbook is ready for the same agent/model upgrades after desktop enhancement is completed.
