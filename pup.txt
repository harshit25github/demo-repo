# Task: place marks with icons and Inventory API photos in Manager replies

You are working in our production backend, where the Manager Agent, Trip Planner V2 and Flight Agent already run. Your task is to add **place-mark hydration**:

- After the Manager has written its final reply, the backend marks the places the reply names.
- The client then draws an icon for each place's kind, and shows a photo where we have one.
- Photos come only from our **existing Inventory API**.

This was built and tested in a separate reference codebase that you can't see. Everything you need from it is in this document. Where the reference code names a variable that our production code may name differently, this document says what the value **means**, so you can find our equivalent. Don't guess names; inspect our code.

---

## 1. Rules

1. **Keep the architecture.** The Manager calls the Trip Planner and Flight specialists as tools, exactly as now. Add no agents and no LLM calls. Hydration is plain code that runs after the Manager's final output exists.
2. **Keep streaming.** Hydrate only the final text. Never inject marks into partial deltas, and never into the Manager's own conversation history; the model keeps seeing its plain reply.
3. **Photos only from the existing Inventory API client.** Don't add an image provider, don't fetch images from the web, and never build, guess or placeholder a URL. A place without an Inventory photo gets `photo: null`.
4. **Settings stay in code.** Values such as the 1-second photo timeout are constants, not new environment variables. Reuse the Inventory client's existing auth and config.
5. **No speculative abstractions.** Add only the functions below.
6. **Commit only the files you change.** Run the type check and the existing tests before finishing.

---

## 2. What the client receives

The final reply text marks the **first** mention of each place as a Markdown link with a `place:` reference:

```markdown
Here's your 5-day solo [Tokyo](place:1) plan, one area at a time.
**Day 1 · Old Tokyo:** [Sensō-ji](place:2) early, snacks on [Nakamise-dōri](place:3), then [Tokyo Skytree](place:4).
```

The final `done` payload carries the marks in reply order:

```json
"places": [
  { "ref": "1", "kind": "city",     "photo": "https://<inventory image url>" },
  { "ref": "2", "kind": "temple",   "photo": null },
  { "ref": "3", "kind": "market",   "photo": null },
  { "ref": "4", "kind": "landmark", "photo": null }
]
```

- `ref` is the `N` in `place:N`, counted from 1 in the order the marks appear.
- The place's name is the link text. The list doesn't repeat it.
- `kind` is one of twelve names:
  - The eleven place kinds: `city`, `area`, `landmark`, `temple`, `museum`, `park`, `nature`, `market`, `food`, `nightlife`, `daytrip`.
  - `flight`, which marks the first "flight" or "flights" on a turn that has a flight search.
- `photo` is a URL from the Inventory API, or `null`. Today only cities get a photo.
- The stored assistant message keeps the same list (`message.places`), and loading a chat returns it unchanged.
- **The backend sends no icons.** The client maps `kind` to its icon and loads a photo only when the traveler opens it.

## 5. The marker (new module, copy as-is)

Create a small text module, for example `shared/text/place-marks.ts`:

```ts
/**
 * Place marks: after the Manager's reply is finished, the backend marks the first mention of each place a specialist
 * named as [name](place:N), and the turn carries a places list the client reads to draw an icon for each mark's kind
 * and, where there is one, a photo. The model never writes a mark, so it can't invent a place.
 */

/** Something the reply may name: a place under any of its names, or the word "flight" or "flights". */
export interface PlaceCandidate {
  /** The names a mention can use, such as "Bali" and "Denpasar". The reply keeps the one it wrote. */
  names: string[];
  /** One of the eleven place kinds, or "flight". */
  kind: string;
  photo: string | null;
}

/** One mark in the turn's places list, in reply order. The name is the reply's own text, so the list doesn't repeat it. */
export interface PlaceMark {
  ref: string;
  kind: string;
  photo: string | null;
}

const escapeForPattern = (text: string) => text.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');

/** Text marks never touch: headings, struck text, fenced and inline code, and anything already a link. */
const PROTECTED = [/^[ \t]{0,3}#{1,6}[ \t].*$/gm, /~~[^~\n]+~~/g, /```[\s\S]*?```/g, /`[^`\n]*`/g, /\[[^\]\n]*\]\([^)\n]*\)/g];

/** A capitalized word other than "I" right after a name, on the same line: the name starts a longer one, such as "Tokyo Skytree". */
const LONGER_NAME = /[ \t ]+(?!I\b)\p{Lu}/uy;
const startsLongerName = (text: string, at: number) => { LONGER_NAME.lastIndex = at; return LONGER_NAME.test(text); };

/**
 * Marks the first mention of each candidate, keeping the words exactly as the reply wrote them and any bold around
 * them. Longer names win where names overlap, so "Tokyo Skytree" is the landmark, not Tokyo. A place name followed by
 * another capitalized word is part of a longer name the specialists didn't give, such as "Tokyo Station", and stays plain.
 */
export function markPlaces(markdown: string, candidates: readonly PlaceCandidate[]): { text: string; places: PlaceMark[] } {
  const byName = new Map<string, PlaceCandidate>();
  for (const candidate of candidates) {
    for (const name of candidate.names) {
      const key = name.trim().toLowerCase();
      if (key && !byName.has(key)) byName.set(key, candidate);
    }
  }
  if (!byName.size) return { text: markdown, places: [] };

  // Letters and digits on either side mean another word.
  const names = [...byName.keys()].sort((left, right) => right.length - left.length).map(escapeForPattern);
  const pattern = new RegExp(`(?<![\\p{L}\\p{N}])(?:${names.join('|')})(?![\\p{L}\\p{N}])`, 'giu');
  const spans = PROTECTED.flatMap((rule) => [...markdown.matchAll(rule)].map((match) => [match.index, match.index + match[0].length]));

  const marked = new Set<PlaceCandidate>();
  const places: PlaceMark[] = [];
  let text = '';
  let copied = 0;
  for (const match of markdown.matchAll(pattern)) {
    const start = match.index;
    const end = start + match[0].length;
    const candidate = byName.get(match[0].toLowerCase());
    if (!candidate || marked.has(candidate) || spans.some(([from, to]) => start < to && end > from)) continue;
    if (candidate.kind !== 'flight' && startsLongerName(markdown, end)) continue;
    marked.add(candidate);
    const ref = String(places.length + 1);
    places.push({ ref, kind: candidate.kind, photo: candidate.photo });
    text += `${markdown.slice(copied, start)}[${match[0]}](place:${ref})`;
    copied = end;
  }
  return { text: text + markdown.slice(copied), places };
}
```

Worked example:

```ts
markPlaces('Your **Bali** plan starts at Tirta Empul, then Bali again.', [
  { names: ['Tirta Empul'], kind: 'temple', photo: null },
  { names: ['Bali', 'Denpasar'], kind: 'city', photo: 'https://<inventory url>' },
]);
// text:   'Your **[Bali](place:1)** plan starts at [Tirta Empul](place:2), then Bali again.'
// places: [{ ref: '1', kind: 'city', photo: 'https://<inventory url>' }, { ref: '2', kind: 'temple', photo: null }]
```

## 6. The link sanitizer (two changes)

A `place:` link the model writes itself must be stripped like any other link. The final check must then let through only the marks the backend issued.

```ts
// 1. Add `place:` to the Markdown link pattern, so model-written place links are removed by sanitizeNoLinks:
const MARKDOWN_LINK_PATTERN = /\[([^\]\n]+)\]\(((?:https?:\/\/|www\.|place:|[a-z0-9.-]+\.[a-z]{2,})[^)\s]*)[^)]*\)/gi;

// 2. New export next to assertNoLinks:
/** assertNoLinks for a reply the backend added place marks to: those exact references pass, anything else still fails. */
export function assertOnlyIssuedLinks(text = '', issued: readonly string[] = []): void {
  const allowed = new Set(issued);
  assertNoLinks(String(text || '').replace(/\[([^\]\n]+)\]\(([^)\s]+)\)/g, (link, label, url) => (allowed.has(url) ? label : link)));
}
```

## 8. Hydration in the Manager runner

### 8.1 What the reference code's names mean

Map each name to ours before you paste anything:

| Reference name | Meaning |
|---|---|
| `appContext` | The request state object the Manager and specialists share for this turn. |
| `appContext.tripPlanner.suggestions` | Trip's chip list. Trip saves a new array each time its result is saved, so "different from before the run" means Trip ran this turn. |
| `appContext.tripPlanner.options` | The destinations Trip suggested. They're replaced only when Trip suggests new ones. Each has `code` (an IATA code or null) and `city`. |
| `appContext.tripPlanner.plan` | The saved plan. `plan.destination` is `{ city, iata }`, and `plan.days[]` holds the saved days with their `places`. |
| `flightTurn.flightRan` | True when the Flight agent ran in this turn. |
| `appContext.flight.searchKey` | Set when a flight search exists in state. |
| `appContext.flight.segments[0]` | The current search's first leg: `{ origin, destination, origin_iata, destination_iata }`. |
| `log(level, event, data)` | Our structured logger. |

### 8.2 Helpers (put them next to the runner)

```ts
/** The cities a reply may name: the options Trip suggested this turn, if it ran and suggested any, and the plan's city. */
function tripDestinations(trip: TripState | undefined, optionsBefore: unknown): DestinationRef[] {
  const options = trip?.options && trip.options !== optionsBefore ? trip.options : [];
  const planCity = trip?.plan?.destination;
  return [
    ...options.map((option) => ({ iata: option.code, city: option.city })),
    ...(planCity ? [{ iata: planCity.iata, city: planCity.city }] : []),
  ];
}

/** A flight search's route cities. */
function routeCities(flight: FlightState): DestinationRef[] {
  const segment = flight.segments?.[0];
  return segment
    ? [{ iata: segment.origin_iata ?? null, city: segment.origin || null }, { iata: segment.destination_iata ?? null, city: segment.destination || null }]
    : [];
}

/** A city as a mark candidate under its own name and the Inventory's names for it, with its photo when there is one. */
function cityCandidate(city: DestinationRef, photos: readonly CityPhoto[]): PlaceCandidate | null {
  const lower = (value: string | null | undefined) => String(value ?? '').trim().toLowerCase();
  const photo = photos.find((entry) => (city.iata && entry.codes.includes(city.iata.toUpperCase()))
    || [entry.name, ...entry.aliases].some((name) => lower(name) === lower(city.city)));
  const names = [...new Set([city.city, photo?.name, ...(photo?.aliases ?? [])].filter((name): name is string => !!name?.trim()))];
  return names.length ? { names, kind: 'city', photo: photo?.photo ?? null } : null;
}

/** The named places of the saved plan, by kind. Plain names saved before kinds existed stay unmarked. */
function planPlaces(trip: TripState | undefined): PlaceCandidate[] {
  return (trip?.plan?.days ?? []).flatMap((day) => dayPlaces(day).flatMap((place) => (place.kind ? [{ names: [place.name], kind: place.kind, photo: null }] : [])));
}

/** The word "flight" or "flights", marked with the flight icon on a turn with a flight search. */
const FLIGHTS: PlaceCandidate = { names: ['flights', 'flight'], kind: 'flight', photo: null };

/** How long a finished reply waits for its photos before it goes out with marks but no photos. */
const PHOTO_LOOKUP_TIMEOUT_MS = 1000;

/** The photos a lookup found, or none when it fails or runs past timeoutMs: photos never fail a reply or hold it up. */
async function photosOrNone(lookup: () => Promise<CityPhoto[]>, timeoutMs: number, requestId: string): Promise<CityPhoto[]> {
  let timer: ReturnType<typeof setTimeout> | undefined;
  const timedOut = new Promise<null>((resolve) => { timer = setTimeout(resolve, timeoutMs, null); });
  try {
    const photos = await Promise.race([Promise.resolve().then(lookup), timedOut]);
    if (!photos) log('warn', 'manager.photo_lookup_timed_out', { requestId, timeoutMs });
    return photos ?? [];
  } catch (error) {
    log('warn', 'manager.photo_lookup_failed', {
      requestId,
      errorName: error instanceof Error ? error.name : 'UnknownError',
      errorMessage: error instanceof Error ? error.message : String(error),
    });
    return [];
  } finally {
    clearTimeout(timer);
  }
}
```

`TripState` and `FlightState` are our own trip and flight state types.

```ts

  ...existingResultFields,
```
