Important context:

* Same API key is being used.
* The model still works with `client.chat.completions.create(...)`.
* The model fails with direct `client.responses.create(...)`, even without tools:

```ts

  model: "ft:our-model-id",
  input: "test",
});
```

So this is probably not only an Agents SDK issue.

   * organization
   * project
   * baseURL
   * OpenAI SDK version

   * endpoint being called
   * model ID
   * org/project/baseURL config
   * full OpenAI error object
   * request ID from the failed Responses call
4. Test the same model with:

   * `client.chat.completions.create(...)`
   * `client.responses.create(...)`
   * Agents SDK default flow
   * Agents SDK forced to `chat_completions` using `setOpenAIAPI("chat_completions")`
5. Check whether any hosted/built-in tools are being passed in the Responses/Agents flow.
6. Check package/version changes around the time this started failing:

   * `openai`
   * `@openai/agents`
   * lockfile changes
   * env/config changes
7. Create a minimal reproducible script that only initializes the OpenAI client and calls both endpoints with the same `ft:` model ID.

Expected output:

* A clear comparison of which endpoint works/fails.
* The exact error body and request ID for the failing Responses call.
* Whether this is code/config-related or likely an OpenAI-side Responses API model routing issue.
* If Responses keeps failing but Chat Completions works, propose a temporary fallback using Chat Completions for the fine-tuned model path.
