Hi team, we are seeing an issue in the Puppeteer cron automation.

Some batches have a high number of bookings, so one cron execution takes longer to complete. Before it finishes, the next cron starts, causing both jobs to run in parallel.

This can create booking conflicts, duplicate processing, and Puppeteer crashes.

Can we please review the cron timing or add a lock mechanism so the next cron does not start until the previous one is completed?
