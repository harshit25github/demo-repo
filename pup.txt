Enhance our **Nexus Service chat UI** to support switching between **Gateway Agent** and **Manager Agent** approaches.

The backend already supports architecture selection through the `/user/chatting` POST API. We now need to integrate this into Nexus.

### Requirements

**1. Architecture Selection Dropdown**
- Add a clean, modern dropdown directly in the chat interface.
- Options: **Gateway** and **Manager**.
- Default selection: **Gateway**.
- Place it near the chat header or input area, wherever it fits naturally without cluttering the UI.
- Clearly display the currently selected approach.

**2. API Payload Integration**

When sending a chat request, include the selected architecture in the existing orchestration payload.

- Gateway selected → `platform: "gateway"`
- Manager selected → `platform: "manager"`

Inspect the actual `/user/chatting` API contract and use its existing payload structure. Do not assume the location of the `platform` field.

**3. Chat Experience**
- Users should be able to switch approaches easily to compare their behavior.
- Ensure the selected approach is consistently passed in subsequent chat requests.
- Preserve existing streaming, acknowledgements, chat history, and error handling.
- Avoid mixing Gateway and Manager conversation context when switching approaches. Inspect the existing session behavior and handle this appropriately.

**4. UI/UX**
- Keep the design minimal, polished, and consistent with Nexus's existing styling.
- Prefer reusing existing dropdown components.
- Make the selection intuitive and responsive across screen sizes.

### Implementation

First inspect the current Nexus chat UI, API integration, and session management. Then implement the simplest reliable solution.

Avoid unnecessary components, wrappers, or architectural changes.

**Goal:** Allow users to switch between Gateway and Manager directly from Nexus chat and test both approaches using the correct backend payload.

Finally, summarize the files changed, API payload mapping, and testing results.
