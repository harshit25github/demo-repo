We need your input on one design decision for chat history and flight search context.

Currently, we have a **chat table** where we store flight-related context at the **chat ID level**. The **messages table** stores all messages, and each message is linked to the chat using `chat_id` as a foreign key.

Now the question is: should we also store the flight context against each individual `message_id`?

This means each message would have its own exact flight search context, such as selected filters, search details, and contracts used at that time.

If yes, we also need to decide how to refresh that context when loading chat history:

Option 1: Refresh all flight contracts/context when the chat history is loaded.

Option 2: Refresh only the contracts/context for messages that are visible, for example when the user scrolls to them.

Option 3: Keep the stored context as it was originally, without refreshing, so the old chat remains exactly the same as when it was created.

Please confirm which approach we should follow.
