Create a debugging suite for my existing flight API service to understand the complete flow between:

1. Flight Search API
2. Apply Filter API

Goal:
Help me debug how cookies, UUIDs, searchId/sessionId/correlationId, headers, and payload values move from the first API call to the next.

Tasks:
- Identify where Flight Search API and Apply Filter API are called in the codebase.
- Create a script: npm run debug:flight-flow
- Run Flight Search API with a sample payload.
- Capture request headers, response headers, Set-Cookie, cookies sent, response summary, and IDs/UUIDs returned.
- Store cookies in a cookie jar and reuse them for Apply Filter API.
- Run Apply Filter API using the correct cookies and IDs from Flight Search.
- Log which cookies and IDs are required for the second API.
- Mask sensitive cookie/token values in logs.
- Add tests to verify:
  - Search API returns required IDs.
  - Cookies are captured after search.
  - Filter API reuses required cookies and IDs.
  - Filtered results are returned successfully.
- Generate a markdown doc: docs/flight-api-flow-debug.md explaining:
  - API sequence
  - Cookie flow
  - UUID/searchId flow
  - Required dependencies
  - Failure points

Constraints:
- Do not hardcode real cookies/tokens.
- Do not expose full cookie values.
- Keep cookies/session handling inside backend, not inside the AI agent.
- Final output should help convert this flow into clean agent tools: searchFlights() and applyFlightFilters().
