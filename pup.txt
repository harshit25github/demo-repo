# Goal: Production Manager Agent Intelligence & Response Stabilization

Thoroughly review, improve, and test our existing **Manager + Flight Agent + Trip Planner V2 architecture**.

Our primary problem is not tool execution. The specialists are often returning useful feedback, but the **Manager is not using that intelligence effectively**. Its responses are too short, robotic, and lack acknowledgement, engagement, and meaningful guidance.

We need to fix this properly, not through unnecessary wrappers or hardcoded response handling.

## 1. Model Configuration

Start with the following configuration:

- **Manager Agent → GPT-5.5**
- **Flight Agent → GPT-5.2**
- **Trip Planner V2 → Keep the current configured model initially**

First evaluate this configuration thoroughly.

If Flight Agent intelligence or feedback quality remains insufficient, we can consider upgrading it to GPT-5.5 later, but only with clear evidence.

Avoid repeatedly switching models during testing. Keep the configuration fixed so we can measure whether improvements come from the model or prompt changes.

## 2. Manager Intelligence — Highest Priority

Our Manager should behave like a **sophisticated AI travel advisor**, not a simple input-output chatbot.

Evaluate and improve its ability to:

- Understand short, incomplete, misspelled, ambiguous, and keyword-only queries.
- Leverage conversation history and existing application context.
- Understand implicit references such as "second one", "cheaper", "same trip", or "change that".
- Infer reasonable information without making unsupported assumptions.
- Ask only necessary clarification questions.
- Understand user preferences, intentions, and changing requirements.
- Proactively guide users toward useful travel decisions.
- Generate intelligent, contextual follow-up questions and CTAs.

The objective is to help users progress naturally through their travel experience, even when they provide very little information.

## 3. Fix Robotic Manager Responses

Our Flight Agent already produces rich and meaningful feedback, but the Manager often reduces it to a single-line response.

This is unacceptable for our intended user experience.

Improve the Manager prompt so it produces:

- Natural, meaningful acknowledgements.
- Friendly, welcoming, conversational responses.
- Strong contextual personalization.
- Appropriate emoji-rich and visually engaging content.
- Useful explanations of available options and results.
- Relevant suggestions and next actions.
- Intelligent CTAs that move the conversation forward.

**Important:** Do not force long responses for every message. The response should be proportional to the user's intent and the information available.

A short confirmation can remain short, but meaningful flight results, recommendations, and travel-planning responses should not lose useful specialist information.

Avoid repetitive acknowledgements, fixed templates, unnatural enthusiasm, and generic questions.

## 4. Improve Trip Planner Presentation

Current itinerary responses sometimes follow a rigid structure like:

`Day 1 → Morning → Afternoon → Evening`

This can feel unnecessarily mechanical.

Give the Manager more flexibility to present travel plans naturally and attractively.

- Use engaging descriptions and useful recommendations.
- Adapt presentation to the user's request.
- Highlight experiences rather than mechanically listing activities.
- Use icons, relevant visual elements, and clear Markdown.
- Preserve important itinerary details, dates, activities, and context.
- Follow required client-rendering contracts without forcing unnecessary textual templates.

The Manager should be intelligent enough to decide how best to present the information.

## 5. Review Gateway Prompt & Routing Intelligence

Thoroughly compare our existing **Gateway Agent prompt** against the current **Manager Agent prompt**.

The Gateway previously prioritized Flight Agent routing because the handoff architecture generally transferred control to one specialist at a time.

Our Manager architecture is different.

It can coordinate **Flight Agent and Trip Planner V2 together** when the user's request requires both.

Therefore:

- Do not blindly carry over Gateway routing priorities.
- Identify useful intent-understanding intelligence from the Gateway prompt.
- Remove obsolete single-handoff assumptions.
- Ensure Flight and Trip Planner receive appropriate requests.
- Use both specialists when they provide complementary value.
- Combine specialist findings into one coherent, useful response.
- Avoid unnecessary specialist calls when existing context already answers the question.

Routing should depend on **actual user intent and conversation context**, not outdated Gateway priorities.

## 6. Optimize the Manager Prompt

Review the entire Manager system prompt thoroughly.

We should have a **well-defined, structured, compact Markdown prompt** aligned with current OpenAI prompting guidance for the configured model.

Focus on:

- Removing duplicated instructions.
- Identifying and resolving contradictory rules.
- Removing obsolete Gateway assumptions.
- Removing unnecessary restrictions on response flexibility.
- Keeping responsibilities and priorities clearly organized.
- Separating routing, specialist coordination, and response presentation rules.
- Preserving useful existing intelligence.

Do not blindly expand the prompt. Improve its quality, clarity, and consistency.

Use targeted few-shot examples only where they solve actual observed problems.

## 7. Comprehensive Multi-Turn Testing

First inspect the existing testing infrastructure and reuse available scripts/test cases.

Test three major categories:

**A. Flight-focused conversations**
- Flight searches and modifications.
- Short and ambiguous flight requests.
- Filtering, pricing, and existing flight context.
- Rich Flight Agent feedback being correctly communicated by the Manager.

**B. Trip-planning conversations**
- Destination discovery.
- Itinerary generation and editing.
- User preferences and history understanding.
- Natural, attractive itinerary presentation.
- Relevant follow-up questions and recommendations.

**C. Mixed Flight + Trip Planner conversations**
- Requests requiring both specialists.
- Switching between flights and itinerary planning.
- Combined travel recommendations.
- Understanding previous selections and conversation context.
- Correct sequencing and coordination of specialist calls.

Make the queries realistic. Users often provide only keywords, incorrect city names, incomplete details, or vague instructions.

### Execution Strategy — Mandatory

Run **one multi-turn conversation at a time**.

For each conversation:

1. Inspect Manager reasoning outcomes and routing decisions through available traces.
2. Review specialist tool calls and actual feedback.
3. Compare specialist feedback with the Manager's final response.
4. Check for missing information, robotic responses, weak acknowledgements, incorrect routing, or poor CTAs.
5. Investigate actual failures and identify their root causes.
6. Make targeted improvements.
7. Re-run the affected test to validate the fix.
8. Continue only when the current conversation is stable.

Do not run everything together or waste OpenAI API tokens on repeated tests without a clear debugging purpose.

## 8. Evaluation & Success Metrics

Evaluate:

- Intent understanding accuracy.
- Routing and multi-specialist coordination accuracy.
- Context/history utilization.
- Specialist feedback preservation.
- Response completeness and correctness.
- Conversational naturalness and personalization.
- Acknowledgement and tone quality.
- CTA relevance.
- Itinerary presentation quality.
- Token usage and latency.

Provide measurable pass rates where possible, with clear evaluation criteria and actual evidence. Distinguish subjective quality scores from objectively verified behavior.

## Engineering Constraints

- Keep the existing production architecture and context schemas intact.
- Preserve working Flight Agent and Trip Planner intelligence.
- Keep domain-specific recovery and tool behavior inside specialists.
- Prefer prompt improvements over hardcoded conversational handling.
- Avoid unnecessary wrappers, adapters, factories, and tracking mechanisms.
- Keep code and prompt changes minimal and maintainable.
- Do not change model configurations during an evaluation run.

## Final Objective

We want a Manager that **understands users, intelligently coordinates specialists, preserves valuable findings, communicates naturally, and proactively guides users toward their travel goals**.

The objective is not simply to pass tests or generate longer answers.

We need a **reliable, intelligent, engaging travel assistant**.

Start by auditing the current Manager prompt, Gateway routing rules, and existing test results. Apply targeted improvements, then test the initial GPT-5.5 Manager + GPT-5.2 Flight Agent configuration with one realistic multi-turn conversation before expanding testing.
