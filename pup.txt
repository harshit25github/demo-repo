We checked this session and it was a very long conversation with a high token count. In such long-context cases, response/prompt drift can rarely happen because the :::cards format is enforced through prompt instructions, which are soft rules, not hard validation.

We use this soft-rule approach because a single agent response can be either Markdown or JSON, not multiple formats at once. So card data is embedded inside Markdown using the agreed format.

That said, the final response/state is protected. In the final status_dump, we have added hard verification and regex-based fallback handling. So even if streaming chunks miss the expected format, the final output gets normalized and updated as per the discussed rules.
