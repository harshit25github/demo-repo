You are building a Retrieval-Augmented Generation (RAG) system.

For the same user query, you receive retrieved chunks from multiple retrieval approaches such as:
- embedding
- hyde
- keyword

Each retrieval result contains:
- chunk_id: unique identifier of the chunk
- text: content of the chunk
- score: relevance score returned by that retrieval approach
- approach: name of the retrieval strategy

The same chunk may appear in results from more than one approach.

You are also given:
- the original user query
- a weight for each retrieval approach
- top_k, the number of final chunks to return

Your task is to write a function that returns the final top_k most relevant unique chunks.

Answer Key

1) What is RAG and why is it used?
Answer:
RAG stands for Retrieval-Augmented Generation. It retrieves relevant information first and then gives that context to the LLM before answering. It is used to ground answers in real data, reduce hallucinations, and work with private or frequently changing knowledge.

2) What is the difference between fine-tuning and RAG?
Answer:
Fine-tuning changes the model’s behavior by training it on examples. RAG does not change the model; it gives relevant information at runtime. Fine-tuning is better for behavior and style, while RAG is better for dynamic knowledge.

3) Why do we use vector databases in GenAI systems?
Answer:
Vector databases store embeddings and support semantic search. They help retrieve content that is meaningfully similar to the user’s query, even when exact keywords do not match.

4) How would you reduce hallucinations in an LLM-based application?
Answer:
Use RAG with trusted sources, write strong grounding prompts, keep temperature low, return citations, add validation checks, and allow the model to say “I don’t know” when context is missing.

5) What is the difference between a system prompt and a user prompt?
Answer:
The system prompt defines the assistant’s role, rules, and behavior. The user prompt is the actual request or question from the user.

6) How would you evaluate whether a GenAI application is performing well?
Answer:
Check answer correctness, faithfulness to source, retrieval relevance, hallucination rate, latency, cost, and user feedback. For RAG, evaluate retrieval quality and answer quality separately.

7) What are common challenges while building LLM applications in production?
Answer:
Common challenges include hallucinations, latency, high token cost, poor retrieval quality, prompt injection, inconsistent outputs, privacy concerns, and difficulty in evaluation and monitoring.

8) What is prompt engineering? Improve a weak prompt with a better one.
Answer:
Prompt engineering is the process of writing clearer and more structured prompts to get better outputs.

**Weak prompt:**  
“Give me a diet plan.”

**Better prompt:**  
“You are a diet-planning assistant. Create a 7-day vegetarian Indian diet plan for weight loss. Avoid peanuts. Keep it affordable. Return the answer in a table with calories per meal.”

9) How would you build a simple document question-answering system using Python and an LLM?
Answer:
Extract text from documents, split it into chunks, create embeddings, store them in a vector database, retrieve relevant chunks for a user query, and pass those chunks to the LLM to generate the final answer.

10) Suppose the model gives inconsistent answers to the same question. How would you troubleshoot that?
Answer:
Check if the prompt, retrieval results, chat history, model parameters, or temperature are changing. Log the full pipeline and compare the retrieved context and final prompt across runs.

11) You need to build a chatbot that answers questions from company PDFs. How would you design it end to end?
Answer:
Ingest PDFs, extract and clean text, chunk the content, generate embeddings, store them with metadata, retrieve relevant chunks on query, optionally rerank them, and send the best context to the LLM. Return answers with citations.

12) A user asks a question, but the model answers with made-up information. How would you detect and reduce that?
Answer:
Detect it by checking whether the answer is supported by retrieved context. Reduce it by improving retrieval, forcing grounded answers, adding citations, lowering temperature, and using fallback responses when evidence is weak.

13) Your GenAI app is becoming expensive because of token usage. What steps would you take?
Answer:
Shorten prompts, reduce unnecessary chat history, retrieve fewer but better chunks, cache repeated responses, limit output length, summarize old context, and use a smaller model where possible.

14) Users complain that responses are too slow. Where would you investigate first?
Answer:
Break latency into steps: retrieval, reranking, model inference, network time, and frontend rendering. Then identify which stage is slow and optimize that stage first.

15) You have sensitive business data. What precautions would you take before sending data to an LLM?
Answer:
Minimize the data sent, mask sensitive fields, use approved secure deployments, encrypt data in transit and at rest, enforce access control, review retention policies, and maintain audit logs.

16) When would you choose RAG over fine-tuning?
Answer:
Choose RAG when the answer depends on documents or knowledge that changes often. Choose fine-tuning when you want more consistent behavior, tone, or output format.

17) If retrieved documents are irrelevant, what areas would you debug?
Answer:
Check chunking strategy, embedding quality, metadata filters, query rewriting, vector index setup, search settings, and reranking logic.

18) How would you store chat history for a conversational AI assistant?
Answer:
Store user messages, assistant messages, timestamps, and session IDs. Keep recent history directly, summarize older history, and apply privacy, retention, and access-control rules.

19) How would you prevent prompt injection in an LLM application?
Answer:
Treat user input and retrieved documents as untrusted, separate instructions from context, restrict tool permissions, validate tool inputs, and add guardrails and adversarial testing.

20) How would you explain your GenAI system to a non-technical stakeholder?
Answer:
I would say: the system first finds the most relevant company information, then uses that information to draft an answer. It works like an assistant that reads the right documents before replying.

21) What is reranking and what problem does it solve?
Answer:
Reranking is a second step after retrieval where the top candidate chunks are reordered using a stronger relevance model. It improves which chunks reach the LLM and increases answer quality.

22) How does an LLM work at a high level?
Answer:
An LLM processes text as tokens, uses transformer layers with attention to understand context, and predicts the next token repeatedly until it forms a response.

23) If you need to write a prompt for a dietician agent, how would you approach it?
Answer:
Define the role, goal, user details, constraints, safety boundaries, and expected output format. For example: user age, diet preference, allergies, goal, budget, and response structure.

24) Why do we use XML tags or structured delimiters in prompts?
Answer:
They separate instructions, context, examples, and user input clearly. This makes the prompt easier to maintain and reduces ambiguity for the model.

25) What is your approach to creating few-shot or multi-shot prompts?
Answer:
Start with a clear task, then provide a few high-quality input-output examples that match the format and behavior you want. Keep examples consistent and include edge cases if needed.

26) If a RAG system is not performing well, how would you handle it?
Answer:
Debug the pipeline step by step: retrieval quality, chunking, embeddings, reranking, prompt design, and final generation. Create test queries and measure each stage separately before making changes.
