Enhance logging for both **Gateway V1 and Manager V2** to generate a **detailed execution timing summary** for every chat request.

### Requirements

1. Track the time taken by each major operation:
   - Chat initialization and request processing.
   - Context hydration and database operations.
   - Guardrail execution.
   - Gateway or Manager Agent execution.
   - Individual specialist execution (Flight Agent, Trip Planner, etc.).
   - Every tool invocation, including repeated calls.
   - Summary extraction, image/icon hydration, and other processing stages.
   - Streaming duration and total end-to-end request time.

2. Once the stream completes, generate **one consolidated log entry** containing a readable timing breakdown.

**Example:**

```text
========== CHAT EXECUTION SUMMARY ==========
Request ID: abc123
Platform: Manager V2

Operation                  Duration
-----------------------------------
Request Initialization      120 ms
Context Hydration           340 ms
Guardrail Execution         450 ms
Manager Execution         2,100 ms
Flight Agent              3,200 ms
Trip Planner              4,500 ms
Flight Search Tool        1,800 ms
Summary Extraction        1,200 ms
Image Hydration             350 ms
-----------------------------------
Total Request Duration    8,900 ms
============================================
```

3. **Important considerations:**
   - Log each agent and tool independently, including multiple invocations.
   - Account for parallel agent execution without double-counting total duration.
   - Include request ID, platform, execution status, and timestamps.
   - Generate the summary once on completion, failure, timeout, or cancellation.
   - Preserve existing logs and streaming behavior.
   - Ensure the summary is visible as a **single Kibana log event**, preferably with structured timing fields for filtering and analysis.
   - Never expose sensitive user data or credentials.

### Implementation

Inspect the existing Winston/logger infrastructure and execution flows for both Gateway V1 and Manager V2.

Implement lightweight timing instrumentation using existing utilities wherever possible. Avoid unnecessary wrappers or architectural changes.

**Important:** This is backend observability only. Do not send the timing summary as an SSE chunk to the client.

**Goal:** At the end of every chat request, I should see one detailed timing summary in Kibana explaining exactly where time was spent, including individual agents, tools, and overall latency.

Implement and verify the behavior for both V1 and V2.
