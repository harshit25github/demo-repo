Conduct a thorough **Price Prediction vs. Digital Flight Search API accuracy R&D** using our existing backend services.

### 1. Objective

We've observed that the dates ranked cheapest by our Price Prediction Service often do not return the cheapest actual flight contracts from the Digital API.

We need to investigate:

- How accurately predicted prices match actual Digital API prices.
- Whether the top-ranked predicted dates are genuinely cheaper.
- Whether lower-priced contracts are available on other predicted dates.
- What discrepancies, limitations, or patterns exist in the prediction service.

**This is an independent API-level R&D. Do not invoke any LLM, Flight Agent, Manager, or Gateway.**

### 2. Select 10 Popular O&D Routes

Choose 10 popular, valid flight routes:

- **6 routes:** Domestic and cross-border travel within the USA and Canada.
- **4 routes:** Popular international routes originating from the USA or Canada.

Use the same 10 O&Ds for both one-way and round-trip testing.

**Total:**
- 10 one-way scenarios.
- 10 round-trip scenarios.

Use **December 2026** as the travel date range.

Keep passenger count, cabin class, currency, and other comparable search criteria consistent. For round trips, use a consistent, reasonable trip duration and valid outbound/return dates.

### 3. Price Prediction Execution

For each O&D and trip type:

1. Invoke the existing Price Prediction Service directly.
2. Retrieve the **top 5 cheapest predicted date options**.
3. Capture their predicted prices and rankings.
4. For round trips, preserve the exact outbound and return date pairs.
5. Record the prediction payload, execution timestamp, and relevant response information.

### 4. Digital API Validation

For each of the top 5 predicted options:

1. Invoke our existing Digital Flight Search API directly using the predicted travel date(s).
2. Retrieve actual available flight contracts.
3. Identify the **lowest-priced valid contract** returned by the Digital API.
4. Compare the actual minimum price against the predicted price for that exact option.
5. Record the number of contracts, price differences, and any missing or unsuccessful searches.

**Do not compare against an arbitrary contract. Always use the cheapest valid contract from the Digital API for the matching date(s) and search criteria.**

### 5. Spreadsheet Reporting

Create an Excel workbook with separate sheets:

**Sheet 1 — One-Way Analysis**

10 O&Ds × Top 5 predicted dates = up to 50 comparisons.

**Sheet 2 — Round-Trip Analysis**

10 O&Ds × Top 5 predicted date pairs = up to 50 comparisons.

Include these columns:

| Field | Description |
|---|---|
| O&D | Origin → Destination |
| Predicted Rank | 1–5 |
| Travel Date(s) | Departure / Return |
| Predicted Price | Prediction Service result |
| Actual Lowest Price | Cheapest Digital API contract |
| Price Difference | Actual − Predicted |
| Difference % | Percentage deviation |
| Actual Price Rank | Ranking among the 5 actual prices |
| Contract Count | Number of returned contracts |
| Status | Match / Difference / No Results / Failure |

Also record request parameters, currency, timestamps, and relevant contract identifiers for traceability.

Add a **Summary sheet** covering all 20 scenarios.

### 6. Important R&D Observations

Analyze the following carefully:

- How often is the #1 predicted date actually the cheapest?
- How often is another date from the predicted top 5 cheaper in the Digital API?
- What is the average and median prediction error?
- How large are the absolute and percentage price differences?
- Does prediction accuracy differ between one-way and round-trip?
- Does it differ between domestic, cross-border, and international routes?
- Are there cases where predictions exist but Digital API returns no contracts?
- Are taxes, fees, currency, trip dates, or search criteria causing inconsistencies?
- Are prediction data freshness, availability, or pricing changes possible contributors?

Separate **confirmed findings** from hypotheses. Do not assume a specific root cause without evidence.

### 7. Execution Approach

- First inspect our existing Price Prediction Service and Digital API implementation to understand the actual contracts and required parameters.
- Create a lightweight standalone R&D script using existing services/configuration.
- No LLM calls, agent execution, or changes to production business logic.
- Execute the tests sequentially or with controlled concurrency, respecting API limits.
- Track failures, execution duration, and request/response details.
- Do not silently discard failed or empty-result cases.

### 8. Final Deliverables

Provide:

1. **Excel workbook** containing the one-way, round-trip, and summary analysis.
2. **Concise R&D report** with accuracy statistics and important discrepancies.
3. **Concrete examples** where predicted rankings contradict actual Digital API prices.
4. **Root-cause hypotheses and recommendations**, supported by test evidence.

**Goal:** Quantitatively determine whether our Price Prediction Service is reliable enough to recommend the cheapest travel dates, and identify where its predictions differ from actual bookable flight contracts.
