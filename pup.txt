## Issue 1: No CTAs after Price Prediction failure

Current flow:
- User selects something like `Cheapest next month`.
- `price_prediction_tool` returns `NO_PREDICTIONS`.
- Agent calls `update_flight_suggested_questions` with `suggestedQuestions: []`.

This should not happen.

Even if prediction fails, generate useful next-step CTAs based on the remaining flight context.

Example:
If route is already known but travel date is still needed, possible CTAs could be:
- Search flights next week
- Search flights next weekend
- Choose another travel date

Requirements:
- Do not expose prediction failure details.
- Do not leave suggested questions empty when useful next actions exist.
- Do not regenerate the same consumed price-prediction intent.
- Keep suggestions flight-related and context-aware.

## Issue 2: CTA selected by user appears again

Conversation flow:
1. CTA: `Show non-stop flights`
2. User selects it.
3. Non-stop becomes active.
4. CTA: `Remove non-stop filter`
5. User selects it.
6. Filter is successfully removed.
7. `Remove non-stop filter` must never remain/reappear as the current CTA after that action.

After a user action is completed, its intent should be considered consumed for the current search phase.

## Issue 3: CTA update failure causes tool loop

After removing non-stop, CTA generation tries to reuse previously generated intents such as:
- `results:cheapest`
- `results:compare_top`

`update_flight_suggested_questions` rejects the payload with `REPEATED_CTA_INTENT`.

After that, the agent starts calling `apply_filter` repeatedly.

Fix this behavior.

If suggested-question update fails because some CTA intents were already generated/used:
- do not repeat the previous business tool call
- generate a fresh CTA set
- retry the suggested-question update at most once
- if fresh useful CTAs cannot be generated, continue normally without looping

## Prompt/intelligence rules

Strengthen Flight Agent instructions:

- Always generate fresh CTAs from current flight context.
- Never regenerate an intent already marked generated/used in the current search phase.
- If user just executed a CTA, treat that CTA intent as consumed.
- Use conversation history plus CTA context to understand what the user already acted on.
- Do not solve CTA duplication by hardcoding phrases.
- Let the LLM generate alternatives intelligently.
- A new flight search/searchKey may reset CTA history and start fresh.
