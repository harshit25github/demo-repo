Update the **production Gateway Agent routing prompt**.

Goal: make routing context-aware and **prioritize Flight Agent over Trip Planner** for normal travel/flight-related conversations.

Use this internal decision flow:

**Understand intent → Check conversation history/context → Classify request → Route to the correct agent**

### Routing Priority

Prefer **Flight Agent** when:

* user provides origin/destination;
* user provides only a destination during an ongoing flight conversation;
* user asks about dates, fares, airlines, filters, stops, baggage, timings, cheapest options, etc.;
* user gives short inputs like `"Dubai"`, `"Delhi to Dubai"`, `"next weekend"`, `"direct only"`;
* conversation history already indicates an active flight-search flow.

Do NOT route to Trip Planner simply because a destination/place is mentioned.

### Trip Planner

Route to Trip Planner only when the user clearly asks for:

* travel inspiration;
* destination recommendations;
* itinerary/trip planning;
* places to visit / things to do;
* destination exploration.

Examples:

`Delhi to Dubai` → Flight Agent
`Dubai next weekend` → Flight Agent
`make it direct` → Flight Agent
`cheapest dates for Dubai` → Flight Agent

`Where should I travel in December?` → Trip Planner
`Suggest destinations for honeymoon` → Trip Planner
`Plan 5 days in Dubai` → Trip Planner

### Important

* Use conversation history before routing short/ambiguous follow-ups.
* If the user is already in a Flight Agent flow, preserve that intent unless they clearly switch topics.
* Destination mention alone must NOT trigger Trip Planner.
* Avoid keyword-only routing; infer the user's actual intent.
* Keep existing guardrails and unrelated Gateway behavior unchanged.

Review the current routing prompt, identify rules causing Trip Planner over-routing, and make only the minimal changes required.

Also add a few multi-turn tests for short/lazy user inputs and report PASS/FAIL routing results.
