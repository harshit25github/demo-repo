Explore Flight Agent date inference issue for vague dates like “next week”, “next weekend”, and “next month”.

Do not implement yet. First debug and suggest the best improvement plan.

## Problem

Flight Agent sometimes fails to infer travel dates from vague user inputs.

Examples:
- “I want to travel next weekend”
- “Find flights for next week”
- “I’m planning to fly next month”
- “Show me flights around August”
- “Maybe this Friday or weekend”

Current issue:
- Agent often says price prediction is unavailable.
- Or it keeps asking for exact date.
- But for normal flight search, we should infer a reasonable date/range from the user’s phrase when possible.

## Expected behavior

If user gives a clear relative date intent:
- “next weekend” → infer upcoming Saturday/Sunday window.
- “next week” → infer next week date range or a reasonable default date.
- “next month” → infer next month window.
- “around August” → infer August window.
- If exact date is required by flight search API, choose a sensible fallback date and clearly mention it.

Do not keep asking for exact date if the user already gave a usable date hint.

## What to investigate

1. Flight Agent prompt
- Check if prompt asks for exact date too aggressively.
- Check if vague date handling is missing or conflicting.

2. Dynamic prompt/context
- Check how date hints are stored in flight context/searchCriteria.
- Verify whether “next week/month/weekend” is preserved across turns.

3. Flight search tool payload generation
- Check where outbound date is finalized before calling `flight_search_tool`.
- Identify if date inference should happen before tool call or inside a small date-normalization helper.

4. Price prediction vs flight search routing
- If prediction is unavailable, agent should still be able to run normal flight search using inferred date.
- Do not stop the flow only because price prediction failed.

## Deliverable

Provide a short report with:
1. Root cause.
2. Where date inference currently breaks.
3. Recommended fix location.
4. Suggested fallback rules for:
   - next week
   - next weekend
   - next month
   - month-only input
5. Risks/edge cases.
6. Files/functions likely to change.
7. Implementation plan.

Do not implement until the plan is reviewed.
